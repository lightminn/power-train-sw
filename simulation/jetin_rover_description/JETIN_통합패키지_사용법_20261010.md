# JETIN 통합 로버 — 2026-10-10

현재 제조사·CAD 기반 근사 모델과 실제 Isaac Sim 검증 결과를 함께 전달한다. 실물 보정이 끝난 디지털 트윈은 아니다. 제조사 공개 사양 중 수치로 사용할 수 있는 속도·토크·분해능·노이즈·범위는 적용했고, 온도·전기·구조 하중 등의 사양은 기록으로 남겼다. 열·전자회로·구조 해석을 수행했다는 뜻은 아니다.

## 열 파일

압축을 풀고 `jetin_rover_description` 폴더 전체를 유지한다. 세 장면 모두 **같은 최신 본체**를 참조한다.

| 목적 | 파일 |
|---|---|
| 평지에서 수동 제어·센서 확인 | `JETIN_Rover_Start_20261009.usda` |
| OV5640 + D435i 비전 집기 | `scenes/JETIN_VisionPick_20261010.usda` |
| 좌우 12cm 파형 주행 | `scenes/JETIN_WaveTerrain_20261010.usda` |
| 전방 랜덤 장애물·L515 확인 | `scenes/JETIN_FrontObstacles_20261010.usda` |
| 공통 형상·관절·센서 설정 본체 | `JETIN_Rover_Final_20261009.usdc` |
| URDF 표시·ROS 작업 | `jetin_rover_isaac.urdf`, `urdf/jetin_rover.urdf` |

본체 파일명 날짜는 기존 참조를 유지하기 위한 것이다. 파일 안의 설정 버전은 `integrated_vision_ready_20261010`이다. 모든 장면의 형상·관절·물성은 이 본체 하나를 공유한다. 원본 Fusion 설계 파일, 제작 DWG·STEP은 패키지에 중복 넣지 않았다.

URDF는 트리 구조이므로 디프런셜 폐루프의 두 연결과 PhysX 설정·센서 런타임을 전부 표현하지 못한다. **Isaac 물리 시험은 제공된 USD로 시작한다.** URDF를 다시 가져오면 같은 검증 설정이 자동 복원되지 않는다.

## 화면에서 수동 실행

Isaac Sim 5.1에서 시작 장면을 연다. Script Editor에서 아래를 실행한다. 경로는 압축을 푼 실제 위치로 바꾼다.

```python
import runpy
runpy.run_path(r"C:\작업폴더\jetin_rover_description\tools\install_jetin_runtime.py")
```

Linux에서는 `/home/.../jetin_rover_description/tools/install_jetin_runtime.py` 형식이다. 열린 `JETIN Rover controls` 창에서 Play를 누른다. 팔·조향 슬라이더는 도 단위, 바퀴는 m/s이다. 구동 명령을 직접 입력하기 전에는 자동 주행하지 않는다. 로커·보기·커넥터는 수동 관절로 두며 구동 슬라이더를 제공하지 않는다.

Snapshot은 현재 카메라·깊이·점군·피드백을 `results/snapshot_...`에 저장한다. Record / finish를 두 번 누르면 전체 보기 영상을 저장한다. MP4 녹화에는 `ffmpeg`가 필요하다. Stop을 누르면 녹화를 마무리하고 물리 실행을 중지한다. 자동 집기·파형 주행은 다음 실행 도구를 사용한다. 장면만 열어 Play를 누르는 것으로 비전 제어 코드가 자동 실행되지는 않는다.

## 자동 시뮬레이션

**Isaac Sim의 Python 환경**에서 패키지 폴더로 이동해 실행한다. WS1에서 검증한 환경은 Linux·Isaac Sim 5.1이다. 일반 시스템 Python으로 실행하지 않는다. GUI 화면 조작 도구는 Windows용 경로도 처리하지만 Windows ROS2 연결은 별도 검증하지 않았다.

```text
python tools/run_jetin.py --scenario vision --film
python tools/run_jetin.py --scenario terrain --film
python tools/run_jetin.py --scenario obstacles --gui
python tools/run_jetin.py --scenario flat --gui --ros2
```

Isaac의 별도 설치형 Python을 쓰는 환경이면 위 `python`을 해당 설치의 `python.sh`/`python.bat` 경로로 바꾼다. 영상은 `results/vision_20261010/` 또는 `results/integrated_terrain_20261010/`에 생성한다. 영상 없이 파형을 검증하려면 `--film`을 생략한다. 비전 시험의 `--seed`는 물체의 크기·위치·방향 난수를 바꾼다. 현재 검출기는 **주황색 직육면체의 RGB 분할**이며 임의의 물체 종류를 인식하는 학습 모델은 아니다.

비전 집기는 D435i의 실제 렌더 RGB·깊이를 정합해 위치를 추정하고, 끝단 OV5640 영상의 방향으로 목표를 보정한다. 관측되지 않는 두께는 상자 형태 가정을 사용한다. 가림이 생기면 마지막 유효 관측을 유지한다. 로버 자세에 맞춰 IK를 다시 풀고 관절 구동으로 접근·닫기·들기·내려놓기를 수행한다. 물체 참값은 결과 평가에만 사용하고 제어기에 제공하지 않는다. 강제 고정·위치 순간이동·물체 부착 제약을 사용하지 않는다.

`OV5640_RGBD_vision_pick.mp4`는 동일한 새 촬영의 전체 보기·OV5640·D435i RGB·깊이를 동기화한 92초 영상이다. 깊이 색상은 0–2m를 표시하며 2m 이상은 포화한다. 가림과 실제 센서 시야 제한도 영상에 남긴다.

## ROS2 인터페이스

기본은 Humble·domain 171·localhost이다. 다른 PC와 통신하려면 실행 전 `ROS_DOMAIN_ID`, `ROS_LOCALHOST_ONLY=0` 및 네트워크 설정을 맞춘다. 로봇 제어 명령을 받는 모드는 `flat/obstacles --ros2`이다. 자동 비전·파형 제어와 외부 ROS 명령을 동시에 적용하지 않는다.

| 출력 | 내용·단위 |
|---|---|
| `/clock` | 시뮬레이션 시간 |
| `/jetin/joint_states`, `/tf` | 관절 참값 rad/rad·s⁻¹, world 기준 강체·센서 변환, 50Hz |
| `/jetin/encoders` | 로커·보기 AS5048B 4개 모델 출력, 60Hz |
| `/jetin/wheel_steering_feedback` | 6바퀴 속도와 4조향각 모델 출력, 50Hz |
| `/jetin/l515/imu` | 가속도 m/s², 각속도 rad/s, 100Hz; 자세 추정값은 없음 |
| `/jetin/{센서명}/image`, `/camera_info` | RGB, 해당 RGB 카메라 내부 파라미터 |
| `/jetin/{깊이센서명}/depth`, `/depth_camera_info`, `/points` | float32 m 깊이·깊이용 내부 파라미터·광학 좌표계 점군 |

센서명: `ov5640_rgb`, `d435i_rgb`, `d435i_depth`, `l515_rgb`, `l515_depth`. 자동 ROS 검증에서는 카메라 10Hz로 전송한다. RGB와 깊이의 내부 파라미터가 다르므로 정합 때 각 `camera_info`를 사용한다. `/tf`는 world 기준 변환이며 로봇의 전체 TF 트리를 별도 ROS 노드에서 중복 발행하지 않는다.

| 입력 | 메시지·단위 |
|---|---|
| `/jetin/arm_steering_command` | `sensor_msgs/JointState`: name + position(rad), CAD 범위 밖·수동 관절 명령 거부 |
| `/jetin/gripper_command` | `std_msgs/Float64`: pinion_A 목표각 rad, pinion_B는 종속 |
| `/jetin/wheel_speed_command` | `std_msgs/Float64`: m/s, ±0.3 범위 |

팔·그리퍼 8개 모터의 4096count·0.229rpm 분해능 피드백은 런타임 `JETIN_MANUFACTURER_MODELS['servo_samples']`에 있다. `/jetin/joint_states`는 이 값과 구분되는 관절 참값이다. 전류·온도·실제 버스 지연은 구현하지 않았다.

## 이번 실행 결과

실제 WS1 Slurm 작업 2048: 영상 기반 위치 오차 평가 약 6.68mm, 들고 있는 구간 최소 상승 97.91mm, 양쪽 손가락 접촉 유지 100%, 내려놓은 후 높이 오차 0.017mm. 그리퍼 랙 관계 최대 오차 0.228mm. 팔 명령과 관절값의 최대 차이는 전체 과정에서 약 2.87°이며 0이라고 표시하지 않는다. 동일 색상 상자 하나에 대한 성공으로 일반 물체·모든 자세의 성공을 보장하지 않는다.

같은 본체의 작업 2047: 좌우 12cm 파형에서 6개 바퀴 통과, 로커 회전 변화 L/R 약 15.49°/15.29°, 보기 약 40.96°/29.51°, 폐루프 최대 오차 약 0.0173mm. 각도 출력에는 엔코더 모델의 잡음·INL·샘플링이 포함된다.

최신 ROS·압축 해제 독립 검증은 `validation/integrated_20261010/`의 보고서를 확인한다. 이전 작업의 보고서는 별도 이력이며 이번 설정의 검증으로 바꿔 표시하지 않는다. 상세 현실성 한계는 `JETIN_현실성_검토_20261010.md`에 있다.

## 최종 독립 실행 검증

별도 압축 해제 폴더의 WS1 작업 **2055** 통과: 모든 USD/URDF 참조 확인, 양의 질량·관성, 상세 충돌 125개, 8개 모터 피드백, 카메라 5개, D435i 점군 180224개·L515 점군 603457개, 수동 UI 생성, Stop→Play 재시작 확인. 이어서 16초 팔·그리퍼·툴체인저 시험도 통과했다. 그리퍼 구동 중 axis5 드리프트는 약 0.00244°, 15° 명령 후 실제 약 15.0023°. 툴체인저 볼 8개가 이동했고 CAD 관계 최대 오차 약 0.000723mm였다. GUI의 모든 버튼을 사람이 조작한 시험은 아니며 UI 생성·자동화된 재시작·출력을 확인한 결과이다.

최신 ROS2 작업 **2052**의 7초 기록: 관절/TF 350회, L515 IMU 700회, 엔코더 421회, 각 이미지·깊이·점군 70회. 센서 시간과 시뮬레이션 시간, 깊이 카메라 정보, 8개 서보 위치 양자화 확인. 제한된 팔·조향 명령은 수신했고 수동 관절 명령은 거부했다. 조향 3° 명령의 실제 최종값 약 2.286°로, 현재 PD·접촉 마찰·데드밴드에 따른 정착 오차를 유지했다.

시험 도구 자체의 누락된 math import 때문에 작업 2051의 마지막 검증이 실패했으며, 수정 후 2052 전체 실행으로 확인했다. 실패한 2051을 통과로 표시하지 않는다. 검증한 파형 기본값은 높이 0.12m·파장 0.9m이고, 선택적인 --wavelength 값이 장면 생성에도 전달되도록 수정했다. 기본 지형 파일의 해시는 변경 전·후 동일했다.

추가 작업 **2061**에서 수동 제어창과 ROS가 같은 런타임을 사용하며 팔·조향 명령을 처리하는 것을 검증했다. Stop→Play 후 새 로봇 핸들로 연결을 갱신하고, 카메라·IMU·엔코더·관절 메시지가 다시 발행되는 것도 확인했다. 재시작·시간 역행 때 이전 센서 시간 캐시를 지운다. 자동 시작 주행은 활성화하지 않는다. 이 실행 중 일부 구간은 우리 좌표계 검사와 domain171을 공유했으므로 메시지 수를 Hz 검증에 사용하지 않는다. Hz는 단독 실행 2052의 결과이다. **2064**에서는 다른 domain으로 분리해 IMU와 카메라 메시지의 모든 좌표계가 TF에 존재하는지 실제 수신 데이터로 확인했다. 이후 검증 도구는 Slurm 작업별 domain을 기본으로 분리한다. 일반 로봇 실행의 기본 domain171은 유지한다. L515 가속도·자이로 광학 좌표계도 world 기준 변환을 제공한다.
