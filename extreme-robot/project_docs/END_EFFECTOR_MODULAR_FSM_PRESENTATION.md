# 모듈형 엔드이펙터 FSM 개발 요약

## 한눈에 보는 결론

로봇팔의 엔드이펙터를 교체해도 **같은 GUI와 제어 흐름 안에서 안전하게 인식·전환·구동할 수 있는 모듈형 제어 구조**를 만들었다.  
핵심은 로봇팔 전체 제어를 다시 만드는 것이 아니라, 엔드이펙터를 독립된 "도구"로 보고 각 도구의 차이는 전용 FSM 안에 넣은 것이다. 따라서 평행 그리퍼, 단일 모터 그리퍼, 청소기처럼 동작 원리가 다른 장치도 공통된 상태 관리와 안전 기준 아래에서 다룰 수 있다.

## 개발 핵심 아이디어

### 1. 도구 교체를 단순 설정 변경이 아닌 “안전한 상태 전환”으로 설계

엔드이펙터 교체는 모터 ID를 바꾸는 일이 아니라, 기존 도구를 멈추고 연결 상태를 확인한 뒤 새 도구의 제어 규칙을 적용하는 과정이다.  
이 과정에서 이전 도구의 명령이 새 도구로 흘러가지 않도록 하고, 확인되지 않은 도구는 움직이지 않게 했다. GUI 역시 현재 선택값이 아니라 실제로 연결·검증된 도구 상태를 기준으로 제어 버튼을 열거나 닫는다.

### 2. 공통 제어와 도구별 제어를 분리

모든 도구에 공통으로 필요한 기능은 한 곳에서 관리한다.

- 연결 상태와 통신 이상 감시
- 비상정지, 분리 상태, 수동/자동 권한 관리
- 도구 변경 요청과 결과 표시
- GUI 상태 표시와 구동 가능 여부 판단

반면 각 도구의 고유한 동작은 별도 FSM으로 분리했다.

- 그리퍼: 열기·닫기·정지·끝점 보정
- 청소기: 방향 전환·가동·즉시 정지
- 서로 다른 모터 구성: 각 장치에 맞는 연결 확인과 구동 준비

이 구조 덕분에 새 엔드이펙터를 추가할 때 기존 로봇팔 제어를 건드리지 않고, 해당 도구의 프로파일과 FSM만 확장하면 된다.

### 3. “보이기만 하는 상태”가 아니라 실제 하드웨어 상태를 제어 기준으로 사용

도구가 선택되어 있어도 실제 모터가 없거나, 통신이 끊겼거나, 오류가 있으면 구동하지 않도록 했다.  
즉 GUI의 초록불이나 선택 목록이 아니라 실제 연결·오류·토크·운전 상태가 제어 권한의 근거가 된다. 이는 도구를 뽑았다가 다른 장치를 연결하는 모듈형 환경에서 특히 중요하다.

### 4. 개발자 검증 흐름과 정상 운영 흐름을 분리

현장 검증에서는 보정이나 작업 FSM 전체를 거치지 않고 모터가 움직이는지 빨리 확인할 필요가 있다. 이를 위해 개발자 직접 구동 경로를 제공하되, 비상정지·통신 단절·하드웨어 오류·물리 안전 범위 같은 최소 안전 장치는 그대로 유지했다.  
정상 운영은 보정된 끝점과 도구 FSM을 따르고, 개발자 모드는 장치 연결과 기본 동작을 빠르게 확인하는 용도로 역할을 분리했다.

## 핵심 시행착오와 해결

### 시행착오 1. 도구 제어만 바꾸면 로봇 모델도 자동으로 바뀔 것이라는 가정

처음에는 런타임에서 도구 프로파일과 FSM을 교체하면 충분하다고 보았다. 하지만 로봇의 기구학 모델은 프로그램 시작 시점에 고정되어 있었다. 그 결과 새 그리퍼가 보내는 관절 정보가 현재 로봇 모델과 맞지 않으면, 경로 계획과 좌표 계산을 담당하는 구성 요소가 오류를 내거나 종료될 수 있었다.

**배운 점**: 도구 교체는 제어 명령의 전환과 로봇 모델의 정합성을 함께 고려해야 한다.  
**해결 방향**: 런타임 도구 계층과 로봇 모델 계층의 경계를 명확히 하고, 모델에 없는 도구 관절 정보는 로봇팔의 기본 관절 정보와 분리해 전달했다. 이를 통해 도구 교체가 로봇팔의 경로 계획 기능을 불필요하게 흔들지 않도록 했다.

### 시행착오 2. 안전 게이트가 많을수록 사용성이 좋아질 것이라는 가정

초기에는 각 단계의 안전 조건을 엄격하게 쌓았다. 그러나 도구 교체 직후 상태 응답이 늦거나 통신이 일시적으로 흔들리면, GUI의 요청 상태가 풀리지 않아 버튼 전체가 잠기는 문제가 생겼다. 또한 사용자는 모터가 왜 움직이지 않는지 알기 어려웠다.

**배운 점**: 안전은 버튼을 계속 막는 것이 아니라, 실패 원인을 명확히 보여 주고 안전한 복구 경로를 제공하는 것이다.  
**해결 방향**: 도구 변경 요청에 완료·거부·시간 초과·취소 같은 명확한 수명주기를 부여하고, 실패해도 GUI가 영구히 잠기지 않도록 했다. 통신 오류는 프로그램 종료로 이어지지 않고 도구를 오프라인 상태로 표시해, 사용자가 연결을 복구한 뒤 다시 시도할 수 있게 했다.

## 발표에서 강조할 가치

이 개발의 성과는 특정 그리퍼 하나를 움직이는 기능이 아니다.  
서로 다른 엔드이펙터를 교체해도 로봇팔의 공통 안전 체계와 사용자 경험을 유지하면서, 각 도구의 특성은 독립적으로 확장할 수 있는 기반을 만든 것이다.

> **한 문장 요약:** 엔드이펙터를 교체 가능한 하드웨어 부품이 아니라, 안전하게 발견되고 검증되며 독립 FSM으로 동작하는 “플러그인형 도구”로 재구성했다.
