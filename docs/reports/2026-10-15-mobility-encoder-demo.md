# 협조구동 카드 배치와 더미 엔코더 변화 검증

사용자가 위치를 정정했다. 별도 `차체 3D` 탭은 제거했고 기존 **협조구동 → 6륜 제어 상태** 카드의 도식 자리에 동일한 CAD 렌더러를 넣었다. 카드 제목은 유지한다. 이후 경량화 요청에 따라 상세 메시를 간략 모델로 바꾸고 모터 기술 상세는 숨겼다.

`/usr/bin/python3 -m operator_console.rover_3d_demo`를 실행하면 같은 실제 GUI의 협조구동 카드에서 더미 엔코더가 계속 변한다. 창 제목과 렌더링 영역에 **더미 엔코더 시연 / 실제 로봇 미연결**을 표시한다. 수신은 임시 격리 UDP 포트, ops 토큰은 존재하지 않는 파일, 로봇 세션·게임패드·CAN/USB는 사용하지 않는다. 화면의 전류·속도도 명시적인 더미 값이다.

최초 시연은 여러 관절을 동시에 움직여 실제 접지 자세로 오해할 수 있었다. 사용자 지적 후 원본 CAD의 기준 자세를 보여주고 네 관절을 하나씩 ±8°만 움직인 뒤 기준으로 돌아오도록 수정했다. 한 관절당4초, 전체16초 주기다. 바퀴 회전·조향·IMU 기울기는0으로 고정한다. 자세 표시는 관절 전방 기구학 시험이며 실제 접촉·폐루프 물리 시뮬레이션을 뜻하지 않는다. 바닥처럼 보이던 격자는 제거했다.

렌더러 고정 높이를 없애고 탭의 남은 높이에 맞춰 확장한다. 1100×680에서는 탭 가용 높이559px/콘텐츠559px, 1600×900에서는779px/779px로 기본 화면의 세로 넘침이 없음을 실제 GTK에서 검사했다. 3D 영역 높이는 각각221px/441px다. 불필요한 기술 상세는 숨기고 중복 제목과 안내를 줄였다. 카메라는 각 부품의 경계와 화면 종횡비로 자동 맞춤한다. 확대 글꼴에서도 기본 화면 전체가 탭 안에 들어간다.

실제 GUI UDP 수신 경로에서 두 자세를 검사했다.

| 관절 | 더미 A(rad) | 더미 B(rad) |
|---|---:|---:|
| 왼쪽 로커 | +0.20 | −0.20 |
| 오른쪽 로커 | −0.10 | +0.15 |
| 왼쪽 보기 | −0.15 | +0.20 |
| 오른쪽 보기 | +0.10 | −0.15 |

두 자세 사이에서 IMU·조향 입력은 동일하게 유지했다. 렌더러의 실제 관절 quaternion 부호와 앞왼쪽 바퀴 세계좌표 변화를 확인했다. 바퀴 팝업의 더미 전류3.50A·회전속도12rpm 표시와 송신 중단 후 미연결 전이도 검사했다. GUI에 별도 `rover3d` 페이지가 없고 렌더러가 모터 카드의 자식이라는 배치 검사도 통과했다.

관련 GTK 검사69개 통과,3개 실패가 있었다. 화면 표시 옵션 기대와 arm safe-disabled 런타임 판정 실패는 이전 작업에서 변경 전에도 재현했다. 협조구동 문구의 오래된 기대(`경로는 열려…` vs 현재 `바퀴2개 점검 필요`) 및 폰트 판정도 확인됐고, 이번 CAD 배치에서 해당 문구·폰트 로직은 변경하지 않았다. 별도 CAD/UDP/두 자세/팝업/단절 검사는 PASS이며 전체 GUI 검사가 모두 통과한 것으로 표시하지 않는다.

실물 엔코더 송신기 연결과 디퍼렌셜 폐루프 해석은 계속 별도 범위다. 운영 입력에는 기존 `operator_console --page mobility`를 사용하며 연속 더미 시연은 위 별도 시험 진입점으로만 실행한다.
