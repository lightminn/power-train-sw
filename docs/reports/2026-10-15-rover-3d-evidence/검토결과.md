# JETIN GUI 3D 자세·모터 상태 표시 검토

검토일: 2026-10-15. 현재 노트북 GUI 소스와 GitHub origin/main(c0fd39afebc7f42d6e65fbbe21bd7f927cee1010), 사용자가 지정한 ZIP을 읽었다. GUI 제품 코드는 수정하지 않았다. Jetson의 jetson-orin.local 이름 해석에 실패해 실물 연결 시험은 하지 못했다.

**판정: 실제 CAD 3D 표시, 관절 측정값에 따른 움직임, 바퀴 선택 팝업 모두 구현 가능하다.** 현재 PC의 GTK3 + WebKitGTK 4.1 + Three.js 0.186.1로 첨부 모델의 렌더링을 직접 시험했다. 실물 자세 표시에는 로커·보기 엔코더 수신 경로가 추가로 필요하다.

- 원본: /home/kimseon/문서/카카오톡 받은 파일/JETIN_로버_최신_URDF_20261007.zip

현재 / 파일시스템의 사용자 가용 공간은 0이다. ZIP이 잘린 원인이 디스크 부족인지는 확정하지 않았다. 시험 파일은 /dev/shm 메모리 임시 공간에 보관했고, 재부팅하면 사라진다. 완전한 USD 시험에는 정상 파일이 필요하지만 복구 가능한 URDF로 이번 표시 검토는 가능했다.

## 형식 선택

| 입력 | 표시 방법 | 검토 판단 |
|---|---|---|
| 첨부 URDF + STL | 링크별 메시를 로드하고 URDF의 parent/child, origin, axis로 관절 회전 | 현재 자료로 가장 직접적. 실제 렌더링 시험 완료 |
| USD | 정상 USD의 시각 메시·변환을 읽거나 GLB로 사전 변환 | 지원 가능. 제공 USD가 잘려 이번 파일의 직접 로드는 미검증. PhysX 관절·Drive·폐루프가 일반 3D 로더에서 자동 실행되는 것은 아님 |
| 조립 STEP | CAD 변환기로 부품별 메시 생성 후 GLB 등으로 변환 | 가능. 어셈블리 배치와 별도로 회전축·피벗·부모자식·센서 매핑을 확인해야 함. 사용자가 제공한 정상 STEP은 없어 직접 시험하지 않음 |

단일 PNG 렌더링 이미지로 저장하면 부품별 관절 제어나 정확한 바퀴 선택이 어렵다. GUI 안에 인터랙티브 3D 장면을 넣는 구성이 적합하다. 표시용 메시를 경량화한 GLB로 만들더라도 각 관절의 피벗과 이름, 링크 구분을 보존해야 한다. 기계 부품을 모두 한 메시로 합치면 안 된다.

## 센서와 관절 연결

| 화면에서 움직일 부분 | 필요한 측정값 | 모델 관절 |
|---|---|---|
| 왼쪽 로커 | 관절 엔코더의 보정된 각도 | ml_rocker_joint |
| 오른쪽 로커 | 관절 엔코더의 보정된 각도 | mr_rocker_joint |
| 왼쪽 보기 | 관절 엔코더의 보정된 각도 | bl_bogie_joint |
| 오른쪽 보기 | 관절 엔코더의 보정된 각도 | br_bogie_joint |
| 앞/뒤 네 바퀴 조향 | 기존 steer_deg | fl/fr/rl/rr_steer_joint |
| 여섯 바퀴 회전 | Hall 기반 바퀴 속도 적분 또는 엔코더 위치 | fl/fr/cl/cr/rl/rr_wheel_joint |
| 차체 기울기 | 장착 보정된 IMU roll/pitch | 로봇 루트 변환 |

바퀴 모터의 Hall 회전값은 로커·보기 관절각을 측정하지 않는다. 모터가 회전해도 다리 각도는 같을 수 있고, 다리는 모터 정지 중에도 지형 때문에 움직일 수 있다. 바퀴 속도나 전류만으로 네 다리 관절각을 유일하게 복원할 수 없다. 차체 IMU도 네 수동 관절각을 모두 대신하지 못한다.

현재 실차 joint_state_bridge_node.py는 로커·보기 값을 0으로 발행한다. 이 값을 실측으로 표시하면 안 된다. 새 CAD의 관절 이름과 예전 CAD 브리지 이름·회전축 부호도 달라 기존 변환을 그대로 재사용할 수 없다.

GitHub 최신 시뮬레이션 전달본에는 AS5048B 4개 센서 모델과 /jetin/encoders(sensor_msgs/JointState) 발행 경로가 있다. 이름과 관절 매핑은 위 표와 일치한다. 이는 Isaac 관절에서 값을 얻는 가상 센서이며 hardware_calibrated=false이고 I2C bus/address도 미설정이다. 검토한 실차 motor_control/ros2/operator_console/scripts에는 이 센서의 하드웨어 수신·GUI 전달 경로가 확인되지 않았다. 따라서 시뮬레이션으로 연결을 먼저 검증할 수 있으나 실물 센서 장착·배선·영점·부호는 별도 확인이 필요하다.

첨부 config/loop_closures.json에는 디퍼렌셜 로드의 URDF 트리에서 잘라낸 닫힘 관절 두 개가 있다. 로커·보기와 바퀴의 회전은 URDF로 표시할 수 있지만 디퍼렌셜 바·연결 로드까지 정확히 따라가게 하려면 기하 제약을 계산해야 한다. 이번 합성 자세 시험은 폐루프 해석을 하지 않았다.

## 재사용할 모터 상태 경로

현재 소스에서 이미 연결된 경로:

ODrive CAN/USB 소유 드라이버 → ChassisManager → /wheel_states → chassis_telemetry_sender → UDP :5005 → operator_console.TelemetrySnapshot.wheel_statuses

재사용 가능 필드: drive_current_a(Iq), drive_turns_per_s(Hall 기반이며 바퀴 단위), command_turns_per_s, steer_deg, steer_current_a, mode, stale, drive_axis_error, steer_fault. IMU roll_rad/pitch_rad도 GUI 계약에 있다.

ODrive CAN GET_ENCODER_ESTIMATES 응답의 위치·속도 중 현재 드라이버는 속도만 캐시한다. 원시 Hall count나 엔코더 위치는 현재 GUI에 전달되지 않는다. 정확한 바퀴 회전 위상이나 raw count가 필요하면 기존 소유 드라이버와 텔레메트리를 확장해야 한다. 모터측 위치는 감속비 5:1과 축별 부호·영점을 적용해야 한다. 속도 적분은 바퀴 회전 연출에는 쓸 수 있으나 절대각 측정으로 부르면 안 된다. Iq를 절대 바퀴 하중이나 배터리 전류로 표시하지 않는다.

현재 송신기 publish_hz 기본값은 2 Hz(설정 허용 상한 10 Hz)다. 모델을 매끄럽게 보이게 하는 렌더 주기와 센서 수신 주기를 분리하고 실제 표본 사이만 보간한다. 더 높은 실제 자세 갱신이 필요하면 송신 경로를 확장한다. 기존 UDP 페이로드 상한은 4096 bytes이며 초과하면 wheel_statuses가 제거될 수 있어, 자세 필드 추가 시 크기·누락 정책을 함께 설계해야 한다. 전류 등 필드별 수신 시각·유효성도 확인해야 한다.

바퀴 클릭은 표시용 링크 이름을 front_left 등 현재 텔레메트리 이름에 매핑하고, 읽기 전용 Gtk.Popover 또는 비모달 창에 최신값을 표시하면 된다. 모델 링크 cl/cr는 텔레메트리 mid_left/mid_right와 대응한다. GUI에서 ODrive USB/CAN을 다시 열지 않는다. 통신이 끊기면 마지막 자세의 시각을 표시하고 오래된 값으로 알리며, 바퀴 회전 애니메이션은 멈춘다.

## 권장 적용 순서

1. 정상 확인한 URDF/STL로 경량 표시 모델을 만들고 협조구동의 현재 Cairo 그림 영역에 GTK WebKit 3D 뷰를 연결한다. 3D 회전/확대와 바퀴 클릭 팝업을 붙인다.
2. 기존 wheel_statuses와 IMU만 연결해 조향·바퀴 회전·차체 기울기·모터 상태를 표시한다. 수동 관절의 미측정 상태를 표시한다.
3. 실물 관절 엔코더 4개의 각도·타임스탬프·유효성 계약을 정하고 영점/부호를 보정한다. 시뮬레이션 /jetin/encoders와 실물 입력을 명시적으로 구분한다.
4. 로커·보기 및 디퍼렌셜 연결부를 검증하고 영상 2채널 동시 부하, 시점 회전 중 클릭, 센서 단절·역순·오래된 값, 재연결을 실제 경로로 검사한다.
