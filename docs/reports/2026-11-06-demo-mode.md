## 2. 설치 경로 시험에서 찾은 기존 결함 — chassis_node 시계 영역 불일치

첫 설치 인수(`demo_resume`)는 D1 시연 정지 대신 `corner_fault` E-stop으로 끝났다. 계측 결과 주행 중에도
`ChassisManager._manual_input_active`가 계속 거짓이었다. `chassis_node._tick_authority`는 게이트웨이가 붙인
`source_received_s`(`time.monotonic()` = CLOCK_MONOTONIC)를 `self._steady_clock`(rclpy STEADY_TIME =
CLOCK_MONOTONIC_RAW)의 `now_s`와 비교한다. 노트북(가동 49시간)에서 STEADY − monotonic = −0.197 s라
`source_stamp <= now_s`가 매 tick 실패했다. 그래서 수동 입력 신선도로 문이 닫히는 사전 점검 분기(D1과 2026-09-10
호스트 CAN 자동 재개)가 설치 노드에서 돌지 않았다.

- 젯슨 실측(11-06, 가동 2.5시간, `NTPSynchronized=no`): CLOCK_MONOTONIC_RAW − CLOCK_MONOTONIC = 10 µs. 지금은
  영향이 작지만 NTP가 동기·보정을 시작하면 차이가 쌓인다.
- 그래서 이 경로가 도는지는 기기 시계 상태에 달렸다. 지금 젯슨처럼 차이가 작으면 호스트 CAN 자동 재개 경로가
  **이미 돌고 있을 가능성이 높고**(CLAUDE.md는 그 운용을 보류로 적고 있다), 노트북처럼 차이가 쌓이면 꺼진다.
  어느 쪽도 의도한 게이트가 아니다.
- 이번 변경에서 시계 영역은 고치지 않았다. 고치면 보류 판단과 상관없이 CAN 자동 재개가 항상 켜지므로, CAN 자동 재개
  허용 게이트를 명시적으로 두는 일과 함께 별건으로 다룬다.
- 대신 D1 판정은 시연 모드에서 입력 신선도와 관계없이 자체 사전 점검 표본으로 한다(`ChassisManager.tick`의
  `recovery_preflight` 분기 앞). CAN 복구 분기의 문은 그대로다. 회귀 시험
  `test_demo_stop_does_not_depend_on_manual_input_freshness`(수정 전 RED 확인).

## 4. Codex 검토

설계 5회 수렴 뒤 구현 검토 4회:

| 회차 | 지적 | 처리 |
|---|---|---|
| 1 | P1 6·P2 1: 취소가 진행 중 1.5초 유지를 일반 시작으로 바꿈, 시연 수동 시작이 오류를 지움, 다른 축 피드백이 오래돼도 D1 완화, 최종 무장이 HOLD 미검사, 주행 중 HOLD 관측이 의도를 안 지움, 연결된 정지 상태 120초 만료 없음, 축별 무장 직전 재확인 없음 | 취소가 유지를 끝내고 자동 유지는 일반 시작으로 바뀌지 않음(세대 검사), 시연 모드 모든 시작에 오류 비지움 무장, 모든 축 신선도 요구, broker·차체가 TELEOP·DRIVE·권한 신선도 요구, HOLD 취소를 앞으로, `since`로 120초, `NoClearArmRefused`로 시작 거부(`arm_refused`) |
| 2 | P1 2: 최종 확인과 송신 사이 취소, E-stop→reset이 옛 요청을 무효화 안 함 | 송신 전용 잠금 + 송신 중 취소면 즉시 `stop`, E-stop·reset도 `disarm_seq` 증가 |
| 3 | P1 1: 보정 정지 플래그를 읽은 직후 취소되면 정지 유실 | 송신 중 취소는 다음 tick이 반드시 보내는 정지 요청에도 등록 |
| 4 | 새 P1/P2 없음 | — |

시계 영역 결함을 이번 변경에서 분리하는 판단에는 Codex도 동의했다. 다만 이 결함을 CAN 자동 재개의 확실한 OFF
게이트로 보면 안 되고, 시계를 고칠 때는 명시적인 복구 허용 게이트를 두는 편이 안전하다는 의견이다.

## 5. 남은 것

- 실차: Wi-Fi 끊김 → 자동 재개, 패드 E-stop → 자동 재개 취소, 실제 MOTOR_FAILED 시연 정지 → 자동 해제 → 재개.
- 시계 영역 불일치 수정 여부(위 2절) — CAN 자동 재개 운용 판단과 함께 결정.
- 남는 위험(설계에서 수용): 펌웨어 `clear_errors`에 기대 오류값 비교가 없어 마지막 확인과 clear 사이 수 ms에 생긴
  새 오류도 지워질 수 있다. 시연 모드에서만, 축마다 60초에 3회, 매번 경고 로그.
