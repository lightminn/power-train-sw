# L515 실시간 오버레이 시험대(`lidar_dev/live_overlay.py` 7판) — 2026-10-22

L515 한 대로 카메라 화면 위 바닥·장애물 표시와 2.5D 지도를 한 창에서 보는 개발·시연용 도구다.

- 지도는 광민 `terrain_map` MapRuntime이 만든다. 카메라 오버레이는 광민 `terrain_overlay` TerrainOverlayRuntime을 노드 대신 그대로 돌려서 쓴다. 광민 코드는 import만 하고 고치지 않는다.
- 10-23 정본 경로(Jetson 실시간 지도·콘솔)를 대신하지 않는다. 기준값(통과·주의·불가) 표시와 실기 확인을 위한 시험대다.

## 1. 구성

| 파일 | 역할 |
|---|---|
| `live_overlay.py` | 본체: 카메라 화면 칠하기(바닥 초록·장애물 빨강·덩어리 상자), 2.5D 지도(위에서 본 판·비스듬히 본 판·광민 콘솔 보기), 장착 캘리브레이션, 화면 녹화, 브라우저 보기 |
| `gm_worker.py` | 광민 두 런타임을 **fork 자식 프로세스**에서 돌린다(지도 처리 틱 100–180 ms·오버레이 틱 약 200 ms가 화면 루프의 GIL을 잡지 않게). 깊이 큐는 2칸이라 넘치면 새 프레임을 버리고, IMU는 8개씩 묶어 보낸다 |
| `ground_est.py` | 화면용 바닥 검출(numpy만): IMU 중력 사전 + 높이 히스토그램의 가장 낮은 큰 면 + 거리 비례 허용폭 가중 재맞춤. open3d가 없어도 된다 |
| `live_map.py` | 광민 지도 스냅숏 → 카메라 기준 격자, 기준값 단계 색, 튐 거르기, 위·비스듬히 그림 |
| `gm_features.py` | 광민 콘솔 화면 기능(오버레이 배지·윤곽·한글 문구, 콘솔 지도 보기, 기록 형식) |
| `mount_calib.py` | 장착 캘리브레이션(키 k): 평지 3 s 동안 바닥면 + IMU 중력으로 숙임·옆·카메라 높이·IMU 보정 회전을 구해 `~/.config/l515-overlay/mount.json`에 저장한다 |
| `webview.py` | 화면 없는 실행(`--headless`): MJPEG·키·클릭을 브라우저로 처리. 인증이 없으므로 신뢰하는 네트워크에서만 쓴다 |
| `tmap_live.py` | 광민 지도만 따로 보는 시험대와 공용 경로·로더 |

## 2. 실행

광민 `feat/l515-terrain-map`(terrain_map·terrain_overlay·operator_console 지도 모듈)이 있는 트리에서 실행한다. 다른 작업트리에 있으면 `L515_TMAP_ROOT`로 지정한다.

```bash
export L515_OUT_DIR=~/l515_recordings          # 저장 화면·지도·녹화·보정 파일(없으면 지금 폴더의 recordings)
export L515_CRITERIA=lidar_dev/config/obstacle_criteria_v0.2.json   # 기본값과 같음 — 다른 기준값 파일이면 바꿈
python3 lidar_dev/live_overlay.py                 # 노트북(창)
python3 lidar_dev/live_overlay.py --headless --serve-host <테일넷 IP>   # 화면 없이 → 브라우저 http://<IP>:8090/
```

- 필요 패키지: numpy, opencv-python(-headless), pyrealsense2(L515 지원판). 한글 문구가 필요하면 Pillow도 설치한다. open3d는 필요 없다.
- ⚠️ Jetson에서는 Gateway가 L515를 단일 소유하므로, 직접 실행 전에 Gateway를 정지한다(CLAUDE.md §7 l515_dashboard). Jetson 실행은 아직 하지 않았다.
- 키:

| 키 | 동작 |
|---|---|
| k | 장착 캘리브레이션 |
| p | 바닥 사전값 |
| w | 화면 녹화(끝나면 H.264로 변환) |
| v | 지도 보기 바꾸기(기준값 단계 → 높이 → 광민 콘솔) |
| `[` `]` | 비스듬히 보기 시점 |
| f | 따라가기 |
| e | 지도 화면 지우기 |
| m | 지도 새로 |
| o | 광민 윤곽 |
| b | 덩어리 상자 |
| r | 기록 |
| s | 화면·지도 저장 |
| g | 중력 확인 |
| q | 끝 |

- 저장소 기본 기준값(v0.2)에는 도랑(`trench_depth_m`)이 없다. 그래서 꺼진 칸과 광민 도랑 문턱을 턱(`step_up_m`) 기준으로 보수 대체한다. `step_down_m`으로 보면 6.5 cm 도랑도 통과로 보이기 때문이다. v0.2.1 이상 기준값을 `L515_CRITERIA`로 주면 그 값을 쓴다.
- 광민 지도는 정지 1 s 동안 자이로 영점을 배운 뒤에 쌓인다. 카메라를 들고 움직이는 동안은 비스듬히 판에 "가만히 두세요 · 흔들림 x°/s"가 뜬다(설계상 정상).

## 3. 검증(노트북 i7-1260P + L515 실기, 10-22)

- 노트북 트리(main 기준)에서 `lidar_dev/tests` 117개 통과. 이 PR 트리(`feat/l515-terrain-map` 기준)에서는 아래 PR 본문의 개수를 따른다. 새 부품 시험 `test_lidar_live_parts.py`는 바닥 높이·숙임·천장 오인, 비스듬히 보기 줄 보존(음성 대조 포함)을 본다.
- 실기 실행:
  - 카메라 30 fps에서 화면 루프 초당 23–30회.
  - 처음에는 광민 두 런타임을 같은 프로세스 스레드로 돌려서 지도가 켜지면 6–8 fps까지 떨어졌다. 자식 프로세스로 옮긴 뒤 지도가 켜져도 23–25 fps를 유지한다.
  - 2 s마다 기록에 카메라 fps·루프 속도·구간별 ms·지도 수신 시간·타일 수·메인 스레드 코어가 남는다.
- 녹화(w): 37–52 s 녹화 3번, 실시간 길이·H.264 변환을 확인했다.
- 이 PR 트리 실기 실행(10-22 22:44): `L515_TMAP_ROOT`·`L515_CRITERIA` 없이 저장소 안 광민 모듈과 기본 기준값으로 실행했다. 45 s 동안 녹화를 켠 채 루프 초당 약 30회(카메라 한계), 지도 알려진 칸 27 %, 종료 코드 0, 끝난 뒤 남은 프로세스 0개였다. 처음 실행은 기본 기준값에 `trench_depth_m`이 없어 KeyError로 멈췄고, 고친 뒤 다시 실행했다.
- 잡음 설정: 신뢰도 문턱 2·QVGA·Max Range 기준 실측에서 가짜 장애물 0 %, 매끈한 바닥 95 % 거리 2.85 m.
- 알려진 한계:
  - 얇은 노트북은 계속 돌리면 보드 센서 기준 발열 제한에 걸린다. 15–20 s씩 클럭이 0.5–1.1 GHz로 떨어지고 그동안 fps도 떨어진다. 앱 탓이 아니며, `--max-fps`로 줄일 수는 있지만 완전히 막지는 못했다.
  - Jetson 실행, 로버 장착 상태 실행, 바깥 바닥은 아직 확인하지 않았다.
