# L515 주행 경로 2.5D 지형 지도 구현 계획

> **실행 방식**: 사용자 지정 — native(이 세션에서 Claude가 Task 순서대로 TDD 구현), **Task마다 Codex 리뷰**(`adversarial-review --base <Task 시작 커밋>`, 수렴까지).
> 이 계획은 PR #15 계획과 달리 **코드 본문을 미리 싣지 않는다** — 사용자가 실행 방식을 이미 정했고(2026-10-18) 기한(10-23)이 짧아,
> 계획은 Task 경계·정확한 인터페이스·시험 목록·완료 조건을 고정하고 코드는 각 Task에서 시험을 먼저 쓰며 만든다. 이 결정의 대가는 계획 단계 리뷰가 코드를 못 본다는 점이며,
> Task마다 Codex 리뷰로 메운다.

**Goal:** L515 depth와 바퀴·자이로로 주행 경로 누적 2.5D 지형 지도를 Jetson에서 만들어 UDP :5010으로 보내고, 콘솔 "지형 지도" 페이지에 음영 지도로 그린다.

**Architecture:** 순수 패키지 `terrain_map/`(계약·설정·기하·국소 칸·평면 추측 항법·분류 지도·스케줄러·런타임) + 얇은 ROS 노드(구독만) + 결정적 재생 CLI + 콘솔 수신·렌더·페이지.

**Tech Stack:** Python 3.10(Jetson ROS Humble)·3.14(콘솔 시스템 python), numpy, opencv(판정기만), rclpy, rosbag2_py, GTK3/cairo/PangoCairo.

**Spec:** `docs/specs/2026-10-17-l515-terrain-map-design.md`(커밋 `aad51f2` + 나이 범위 개정 `64826fa`, Codex 10회차·계획 검토 3회차 수렴). 수치·규칙은 스펙이 정본이다. 이 계획과 다르면 스펙을 따른다.

**브랜치:** `feat/l515-terrain-map`(PR #15 `feat/l515-terrain-overlay` `99e4a46` 위). PR은 #15 병합 뒤 main 기준으로 다시 올린다.

## Global Constraints

- 운용자 시각 보조 전용. 지도 노드는 ROS 토픽을 **구독만** 하고 발행·TF·서비스를 만들지 않는다(스펙 §8.2).
- `terrain_map/`은 rclpy·gi·`powertrain_ros`·`operator_console`·`motor_control`·`rosbag2_py`를 import하지 않는다. `terrain_overlay`는 import한다. `terrain_map/contract.py`는 표준 라이브러리만.
- 콘솔 쪽(`operator_console/terrain_map.py`)은 numpy와 표준 라이브러리만(시스템 python에 scipy·cv2 없음).
- 모든 수치는 `MapConfig` 파라미터(스펙 §4.1 표의 기본값·범위). 범위 밖·상호 불일치는 `ValueError`(조용한 클램프 없음).
- 패킷 ≤ 1200 B(상태·타일 모두 최대 표현 시험). 포트 5010.
- 기존 `odometry`·`imu_tilt`·`state_estimation.py` 코드는 바꾸지 않는다. PR #15 동작은 바꾸지 않는다(판정기·세션 게이트는 기본값 불변 확장만).
- 커밋: 파일 단위 `git add`, `feat(terrain): …한다` 형식 + Co-Authored-By. 미추적 `zetin`·MKS 계획은 넣지 않는다. push는 사용자 확인 뒤.
- 시험 실행: conda `/home/light/anaconda3/bin/python`(PYTHONPATH `motor_control:ros2/src/powertrain_ros`), 콘솔 `/usr/bin/python3`(GTK는 `env -u WAYLAND_DISPLAY GDK_BACKEND=x11 xvfb-run -a`),
  ROS는 로컬 `terrain-ros-test:local`(도메인 77). 1분 넘는 묶음은 백그라운드로.

## Review Focus

1. **실제 바퀴 메시지 → 자세**: 애커만·스키드 선회, 유효 바퀴 일부, 직진(rank 1)에서 최소제곱 속도가 스펙 §4.4대로 나오는지 — Task 4 시험.

### Task 1: 계약·설정 (`terrain_map/config.py`·`contract.py`)
**Produces**
- `MapConfig`(frozen dataclass, 스펙 §4.1 모든 항목·기본값·범위). `MapConfig.validate()`는 생성 시 자동. 상호 검증:
  `tile_cells` 8–16, `depth_pending_max ≥ ⌈pose_wait_s·10⌉+1`,
  `pose_wait_s ≥ lateness_margin_s + 1/(2·process_hz) + input_lag_budget_s`, `support_base_height_m` 설정 시 `support_base_variation_m` 필수이고
  `var ≤ tol < min(obstacle_height_m, ditch_depth_m) − var`.
- **나이 표시 범위**(Codex 계획 P2-3·2회차 P1-1): `age_step_s`(Jetson)와 `stale_display_s`(콘솔)는 다른 프로세스라, 스펙 r10에서 범위를 계약으로 묶었다 —
  `age_step_s` 2.0–10, `stale_display_s` 5–60이면 `31·age_step_s ≥ 62 ≥ stale_display_s`가 항상 성립. 각자 기동 때 범위만 검증하고 밖이면 기동 실패(스펙과 같은 동작).
- `contract.py`: `UDP_PORT = 5010`, `MAX_PACKET_BYTES = 1200`, `SCHEMA_VERSION = 1`, 코드 상수 `FREE=0, OBSTACLE=1, DITCH=2, INSUFFICIENT=4`, `UNOBSERVED_H = -128`.
  `encode_status(dict) -> bytes`, `encode_tile(dict) -> bytes`, `parse_packet(bytes, received_s=None) -> StatusPacket | TilePacket`(위반 시 `ValueError`).
  `pack_cells(h_cm: list[int|None], codes: list[int], age_steps: list[int]) -> str(base64)`, `unpack_cells(str, tile_cells) -> (h_cm, codes, age_steps)`.
  `StatusPacket`/`TilePacket` dataclass(필드 = 스펙 §5.2–5.4), `session_key` 속성.
  - **표현 상한**(Codex 계획 P2-4): 모든 정수 카운터(`sequence`·`version`·`tile_seq`·`map_epoch`·`pose_gaps`·`not_support`·`late_dropped`·`tile_count`) ≤ 2³¹−1,
    `version`·`tile_seq` ≥ 1(0 거부), `tx`·`ty` |값| ≤ 2²⁰, `sent_unix_ns` ≤ 2⁶³−1. `corrector.name` ∈ {identity, height_match}, `corrector.reason` ∈ {identity, flat, no_overlap, rejected, applied}.
    `sender_start_mono_ns` ≤ 2⁶³−1(Codex 계획 2회차 P2). 실수는 인코딩 때 소수 4자리로 반올림(`pose`·`distance_m`·`proc_ms`·`score`·`refresh_cycle_s`·임계값), 범위는 스펙 §5.3. 이 상한으로 만든 최악 표본이 1200 B 이하임을 시험.
**Tests** (`terrain_map/tests/test_contract.py`, conda + 시스템 python 둘 다)

### Task 2: 기하 (`terrain_map/geometry.py`) + 독립 렌더러
**Produces**
- `base_to_optical(pitch_down_deg, roll_deg, yaw_deg) -> ndarray(3,3)` = `P·Mᵀ`, `M = Rz(yaw)·Ry(pitch)·Rx(roll)`, `P` = 장착→광학 치환(스펙 §4.8).
- `base_horizontal_frame(normal, offset, R, t) -> (f, l, foot_xy)`: `f = normalize(R·x̂ − ((R·x̂)·n)n)`, `l = n × f`, `o = −R·t`, `foot_xy = (o·f, o·l)`.
- `base_origin_height(normal, offset, R, t) -> float` = `n·o + d`.
- `Pose2D(x, y, yaw)`, `compose(a, b)`, `inverse(a)`, `transform_points(pose, xy)`.
- `terrain_map/tests/world_render.py`: `render_depth(camera: CameraModel, base_pose_world(z, roll, pitch), mount(R, t), surface_fn) -> uint16[H,W]` — 광선을 세계 높이장(`surface_fn(x, y) -> z`, 계단·도랑·상자 조합)과 교차(광선 진행 + 이분법).
**Tests** (`test_geometry.py`)
- 모든 각 0에서 `Rᵀ·(x,y,z) = (z,−x,−y)`, pitch 20°에서 `R·x̂ = (0,−0.342,0.940)`, 복합각(20,20,30) 왕복, 곱 순서를 바꾼 음성 대조가 실패.
- Codex 반례 세 개(스펙 §7.1): 광학축 투영 24.75 cm·원점 이동 0.171 m·`−Rᵀt` 23.99 cm 구조에서 `(2,0)` 점 base 수평 좌표 오차 < 1 cm.
- 렌더러 자체 검사: 평지에서 판정기 평면 offset이 카메라 높이와 1 mm 안.

### Task 4: 평면 추측 항법·자세 (`terrain_map/odometry.py`, `pose.py`)
**Produces**
- 입력 dataclass: `GyroSample(stamp_s, rx_s, wz)` — **`wz`는 이미 차체 z축**(노드가 `base_to_optical`의 `Rᵀ`로 광학 3축을 변환해 넘김. Codex 계획 P2-1), `WheelReading(name, speed_m_s, steer_rad, cmd_turns_per_s, meas_turns_per_s, valid)`, `WheelSample(stamp_s, rx_s, wheels: tuple)`.
- `WheelLayout(positions: dict[name, (x, y)], wheel_radius_m)`.
- `PlanarOdometry(cfg, layout)`: `add_gyro(sample) -> list[PoseSample]`, `add_wheels(sample) -> list[PoseSample]`, `poll(rx_now_s) -> list[PoseSample]`(수신 정지 판정),
  속성 `epoch`(정수, 연속성 상실마다 +1), `bias_ready`, 카운터 `late_dropped`·`epoch_changes`·`invalid_samples`.
  `PoseSample(stamp_s, x, y, yaw, valid, reason, epoch)` — **표본마다 epoch**. epoch 전환은 표본이 없어도 `epoch` 속성이 바로 바뀌고(Codex 계획 P2-2), 런타임이 매 호출 뒤 비교한다.
  epoch 때 비우는 것: 항법의 자세·큐·소구간 상태. **바이어스는 유지**(스펙 §4.4).
- `solve_body_velocity(wheels, layout, omega, cfg) -> (vx, vy, ok, reason)`(조건수 규칙 포함, 순수 함수).
- `PoseTrack(cfg)`: `add(sample, epoch)`, `pose_at(t) -> (Pose2D|None, reason)`, epoch 바뀌면 비움.
**Tests** (`test_odometry.py`, `test_pose.py`; 바퀴 입력은 `chassis.kinematics`로 만든 실제 바퀴 명령에서 생성 — 시험만 `motor_control`을 import)
- 최소제곱: 애커만 0.5 m/s·조향 1.0 → `(0.5, 0.03915)`, 스키드 비대칭 4개 → 0.5, 직진 rank 1 → `v_y=0`, 조향 0.001 + ±0.001 m/s 교란 → `v_y=0`, `|v_y|` 상한 무효.
- 적분: 애커만 90° 선회·스키드 선회 위치 오차 < 2 cm(단순 평균 음성 대조 14.6 cm·22.3 cm로 실패), 바퀴 200 ms 늦은 도착 선회 < 2 cm·< 0.5°(도착 순 음성 대조 실패).
- 자이로 부호: 반시계 선회(바퀴 기하로 ω > 0)에서 자이로 적분 yaw도 증가 — 부호 반전 주입 음성 대조(agy 2). 실제 bag이 오면 같은 검사를 bag으로.
- 공백: 자이로 200 ms 삼각형 회전 → epoch, 자이로 50 ms 공백 → 유지, 바퀴 0.1 s 공백 → 무효·외삽(`½|a|gap²` 일치), 바퀴 0.5 s → epoch, 스트림 정체(바퀴 stamp 20 ms·수신 25 ms) → `max_stream_skew_s`에서 epoch·큐 상한, stamp 역행 > 1 s → epoch, 늦은 표본 → 버림·카운트.
- 바이어스: 제자리 0.03 rad/s(명령 0.0166) → 정지 아님, 정지 1 s → 첫 평균 그대로·`bias_ready`, 정지 중 stale 구간 → 학습 구간 끊김, 준비 전 `BIAS_PENDING`, 같은 stamp 바퀴 먼저.
- `PoseTrack`: 보간(yaw 감김)·간격 초과·무효·`WAITING`·epoch 비움.
