## 2. 화면 구조

### 최종 배치·저장소 경계 (사용자 추가 지시)

이 절은 아래 초기 배치안보다 우선한다.

- 개발의 메인은 **파워트레인 저장소**다. 신규 GUI, 상태 모델, 명령 어댑터 및 테스트는 이 저장소에 추가한다. `extreme-robot`은 기존 기능·인터페이스를 확인하는 참조이며 이번 작업에서 수정하지 않는다.
- 새 로봇팔 기능은 상단 전용 탭에 모은다. 상위 구성은 기존 `실시간 화면 / 시스템 상태`에 `로봇팔 수동조작 / 로봇팔·도구 캘리브레이션`을 추가한다.
- `로봇팔 수동조작` 탭에 자동 감지/선택 변경, 제어권, 팔·도구 FSM, 차단 이유, 키보드 텔레옵, 그리퍼별 전용 패널, 현재 도구 진단·듀얼 동기화 정보를 배치한다. 상세 진단은 이 탭 안에서 접어둘 수 있게 한다.
- 기존 실시간 화면의 로봇팔·도구 영역과 기존 상세 창에는 실제 상태와 기존 컨트롤의 기능만 연결한다. 새 버튼·진단 영역을 추가해 기존 화면 구성을 확대하지 않는다. 기존 도구 선택 컨트롤은 신규 탭과 같은 선택 상태를 공유하며, 선택만으로 하드웨어 명령을 보내지 않는다. 명시적 변경 요청은 신규 탭에서 수행한다.
- 기존 파일은 가능한 한 수정하지 않는다. 신규 탭·스타일·상태 모델·어댑터를 독립 파일로 추가하고, 기존 파일에는 탭 등록, 콜백 연결, 상태 전달에 필요한 최소 접점만 둔다. 전체 리팩터링·기존 클래스 이동·공통 테마 재작성은 범위 밖이다.
- 팔 측 기능이 현재 공개 인터페이스만으로 연결되지 않는 경우 파워트레인 측 어댑터로 해결 가능한지 먼저 검토한다. 팔 저장소 변경이 필수인 경우 해당 기능을 미연결로 명시하고 별도 협의 대상으로 남긴다.
- 뒤의 예정 파일 목록과 실연결 단계도 이 원칙을 따른다. `extreme-robot` 수정 후보는 이번 개발 범위에 포함하지 않는다.

### 디자인·변경 범위 원칙 (사용자 추가 지시)

- 기존 GTK 콘솔의 색상, 타이포그래피, 여백, 카드, 버튼, 상태 배지, 상세 팝업과 접힌 진단 영역의 디자인을 재사용한다. 새 디자인 체계나 전체 화면 재설계를 도입하지 않는다.
- 기존 화면의 정보 밀도와 조작 흐름을 유지한다. 로봇팔·도구 요약은 기존 위치를 활용하고 추가 조작은 전용 탭/기존 상세 창에 배치한다.
- 탭 추가는 기존 내비게이션 스타일을 따른다. 기존 실시간 화면·시스템 상태의 배치와 기본 진입 화면을 유지하며, 공통 스타일 변경은 가능한 한 피하고 필요한 스타일은 팔 영역에 한정한다.
- 파워트레인 GUI와 동작 시스템은 최대한 변경하지 않는다. 주행 패널, 영상 배치·수신, 게임패드, 운전 시작·정지, 차체 E-stop, 복구·설정, 인증 세션의 기존 동작을 보존한다.
- 차체 제어 정책, CAN/USB 드라이버, 워치독, 차체 인터록 및 운용 서비스는 이번 로봇팔 UI 개발의 수정 대상에서 제외한다.
- 신규 팔 UI와 상태·명령 처리는 독립 모듈로 추가한다. `app.py` 등 공통 파일은 탭 등록과 기존 로봇팔 영역 연결에 필요한 최소 수정만 한다.
- 후속 실연결에서 공통 ops 계층 확장이 필요하면 팔 전용 메시지/어댑터를 추가하는 방식으로 검토한다. 기존 차체 명령의 의미·권한·타이밍을 바꾸지 않으며, 불가피한 공통 변경은 구현 전에 변경 이유와 영향 범위를 별도로 제시한다.
- 화면 검수는 기존 화면과 새 화면을 같은 창 크기에서 비교한다. 파워트레인 관련 코드 변경은 diff에서 따로 점검하고 기존 주행·복구·영상 회귀 검증을 수행한다.

상위 탭은 `실시간 화면 / 시스템 상태 / 수동조작 / 캘리브레이션`으로 구성한다.
기존 `복구 · 설정` 창과 영상·주행 운용 흐름을 유지한다.

| 위치 | 구성 |
|---|---|
| 실시간 화면의 로봇팔·도구 영역 | 실제 감지 도구 우선 표시, 다른 도구 선택 및 변경 요청, 장착 상태, 팔 FSM·도구 FSM, 조작 가능 여부와 이유, 상세 보기 |
| 수동조작 | 제어권 요청·승인 상태, 키보드 텔레옵, 축·속도·자세 관리, 실제 장착 그리퍼 전용 패널 |
| 도구 상세 창 | 현재 활성 도구 ID별 위치·전류/부하·온라인·토크·운전 모드·오류, 듀얼일 때 동기화 |
| 캘리브레이션 | 내부 선택 `로봇팔 / 현재 도구`, 측정·검증·적용·저장 결과와 진행 상태 |

팔 FSM, 도구 FSM, 제어권은 별도 표시한다. MANUAL/FSM 제어권을 팔 작업 상태 또는 차체 운용 모드와 혼용하지 않는다.

## 3. 요구사항별 동작

### A1: 자동 감지 우선 + 선택 변경

- 상태를 처음 받으면 실제 활성 도구가 먼저 표시된다. 관측이 없으면 `감지 대기`이며 임의의 그리퍼를 기본 장착으로 표시하지 않는다.
- `현재 감지 도구`와 `변경할 도구`를 분리한다. 사용자가 변경 후보를 고르는 동안 상태 갱신이 후보를 덮어쓰지 않는다.
- 선택 후 `변경 요청`으로 명시 전송한다. 선택 자체는 하드웨어 변경 명령이 아니다.
- 실제 감지와 요청 후보가 다르면 차이와 백엔드 거부 사유를 표시한다. 드롭다운으로 실제 하드웨어 인식을 강제 덮어쓰지 않는다.
- 요청 상태: 대기·진행·완료·거부·시간 초과·연결 끊김. 완료는 백엔드의 새 활성 도구 상태를 확인한 뒤 표시한다.
- 도구 변경 시 기존 누름 조작을 종료하고 이전 도구의 진단·명령 상태를 비운다. 늦게 도착한 이전 도구 응답은 새 패널에 적용하지 않는다.
- 환경 센서 모듈은 기존 별도 텔레메트리 경로를 유지한다. 현재 팔 백엔드가 지원하는 세 도구와 동일한 교체 명령을 지원한다고 가정하지 않는다.

### A2 / A9: 상태와 차단 이유

- 팔 FSM 상태, `/arm_status` 계약 상태, 도구 FSM 상태를 구분해 한국어 이름과 원문을 제공한다.
- 도구 READY/OPENING/CLOSING/STOPPED/FAULT/CALIBRATION_REQUIRED 등을 표시하고 도구별 상태 차이를 보존한다.
- 구동 불가 이유는 연결 끊김, 오래된 상태, 제어권 미승인, 읽기 전용, 미보정, 오류, 비상정지, 도구 교체 중 등 실제 근거로 설명한다.
- 상태가 오래되면 마지막 정상 값을 현재 정상으로 표시하지 않는다. 버튼은 백엔드 상태와 capability를 바탕으로 갱신한다.

### A3: 제어권

- `수동 제어 요청 / FSM 제어 요청`과 실제 승인 상태를 별도 표시한다.
- 요청 클릭만으로 수동 버튼을 활성화하지 않는다. 팔 측 승인 상태를 기다린다.
- 거부·응답 지연을 표시하고 요청 중 영구 잠금을 방지한다.

### A4: 장착 그리퍼별 전용 패널

- 단일 ID5 그리퍼: 열기·닫기·정지, 현재 위치와 열림 정도, 전용 조그 등 기존 단일 그리퍼 GUI가 제공하는 정상 운용 기능을 매핑한다.
- 듀얼 ID3/4 그리퍼: 열기·닫기·정지, 양쪽 위치·열림 정도·동기화, 기존 동기 조그 기능을 별도 레이아웃으로 제공한다.
- 두 패널은 도구별 컨트롤러로 분리하고 백엔드의 정상 FSM 경로를 사용한다. UI 모양만 바꾼 공통 명령 패널로 처리하지 않는다.
- 캘리브레이션 및 그에 필요한 토크 조작은 캘리브레이션 탭으로 이동한다. 일반 구동 준비에 토크 인가가 필요한 경우 기존 guarded enable 경로를 사용한다.
- 청소기·환경 센서 선택 시 그리퍼 조작을 숨기고 해당 도구 정보만 보여준다.

### A6: 수동조작 탭의 키보드 텔레옵

기존 `keyboard_teleop_node.py`, `teleop_core_node.py`, `robot_arm_gui/teleop_vocab.py`를 기능·키맵 정본으로 대조한다.

- 1~6 축 선택, 방향키/W/S 누름 조그, [/] 속도 조절, space 정지, t 복귀, h home.
- 자세 저장·목록·이동·삭제, freedrive 후 자세 확정/취소, 선택 축/전체 재부팅 등 기존 명령을 UI에서도 제공한다. 실제 키 바인딩은 원본 TUI와 대조하여 누락표를 만든다.
- 축 1~5는 팔 관절이다. 기존 6번 그리퍼 축은 현재 도구가 지원하는 경우에만 연결하며, 레거시 joint 이름을 ID5나 청소기에 그대로 전달하지 않는다.
- 가동범위 측정과 보정 관련 명령은 캘리브레이션 탭에서 제공한다. 기존 기능은 유지하되 일반 수동 화면에서 측정 세션을 실수로 시작하지 않도록 구성한다.
- 단축키 안내·선택 축·현재각·명령 속도·동작 중 상태를 표시한다.
- 누르는 동안만 조그를 보내고 키 해제·탭 이동·포커스 상실·창 닫힘·연결 끊김·제어권 상실 시 조그 종료를 처리한다. 입력란과 팝업에서 방향키/문자 입력을 가로채지 않는다.
- 차체 게임패드 입력과 팔 키보드 입력의 대상 및 권한을 구분한다.
- 기존 stop의 토크 해제 의미, resume의 현재 자세 유지, home의 저장 자세 의미를 보존한다. 임의의 전 축 0 이동으로 대체하지 않는다.

### A10 / A11: 현재 도구 진단과 캘리브레이션

- 상세 도구 진단은 활성 프로파일의 actuator_ids만 표시한다. ID5 장착 시 ID3/4의 이전 값은 남기지 않는다.
- 듀얼 상태에서는 두 위치를 보정 끝점 기준으로 정규화하고 동기화 판정은 백엔드 값을 사용한다.
- 캘리브레이션 탭의 로봇팔 영역: 기어비 → 영점 → 가동범위 흐름, 축별 현재 설정, 측정·검증 결과, 임시 적용·영구 저장 여부.
- 현재 도구 영역: 단일/듀얼 끝점 보정의 시작·개별 조그·열림/닫힘 캡처·검증·저장. 듀얼은 각 모터 끝점과 동기화 결과를 함께 표시한다.
- 기존 구현이 없는 도구 보정은 `지원하지 않음`으로 표시한다. 청소기·환경 센서의 새로운 보정 알고리즘은 범위 밖이다.
- 팔 기어비/영점은 기존 파라미터 임시 적용 및 복사용 결과와, 가동범위 JSON 저장을 구별한다. 도구 YAML 저장과 동일한 영구 저장 기능으로 포장하지 않는다.
- 캘리브레이션 중 일반 조그와 도구 변경을 차단하고, 중단·통신 손실 뒤 진행 상태 및 미저장 결과를 명확히 표시한다.

## 4. 데이터와 명령 연결 설계

| 기능 | 기존 팔 인터페이스/구현 | 콘솔에서 필요한 연결 |
|---|---|---|
| 도구 상태·진단 | `/tool/status`, `/tool/type` | UDP 팔 스냅샷 확장, source freshness, 활성 도구 generation |
| 팔 상태 | `/fsm/state`, `/arm_status` | 별도 필드·각 원천 시각 |
| 제어권 | `/control/mode`, `/control/mode_status` | 요청/승인/거부 상태 |
| 도구 변경 | `/tool/change` | 인증된 요청, 완료 상태 재확인 |
| 그리퍼 제어 | `/tool/fsm_command`, 기존 그리퍼 액션 | 도구별 어댑터, 취소·정지·응답 |
| 키보드 텔레옵 | `/arm/teleop_jog`, `/arm/teleop_cmd`, `/arm/teleop_poses` | 기존 키맵·명령 의미와 권한 경계 유지 |
| 팔 보정 | `calib_control`, `calib_math`, `/arm/calib_status`, 브리지 파라미터 | 측정·계산·적용의 비동기 응답 |
| 도구 보정 | `/tool/calibration_command`, `/tool/dual_calibration_command` | 도구별 세션·진행·검증·저장 결과 |

관측은 `arm_console_bridge_node.py` → UDP 수신 구조를 확장한다. 콘솔은 ROS/SDK/CAN/USB를 직접 소유하지 않는다.
명령은 저장소의 기존 인증 ops 경로를 확장하는 설계가 필요하다. 현재 ops가 팔 조그·보정 명령을 이미 지원한다고 가정하지 않는다.

특히 기존 키보드 텔레옵은 벤치용 직접 position_node 경로이며 MoveIt/팔 FSM 경로와 그대로 병렬 실행할 수 없다.
실연결 전에 동일 모터 단일 소유권, MANUAL 승인, 명령 만료·연결 손실, 정지 의미를 확정한다.
GTK 입력부와 명령 추상 인터페이스를 먼저 만들고, 후속 연결 단계에서 팔 측 어댑터가 필요한 변경을 별도 범위로 제시한다.
누름 조그는 일반 버튼 ACK 큐에 무제한 적재하지 않는다. 최신값·만료·명시 종료 계약을 설계한다.

아래 순서가 앞선 UI 선행/실연결 최종 단계 설명보다 우선한다.

1. **기존 UI 연결 계약 확인**: 기존 위젯별 원천 토픽·필드·단위·신선도와 실제 팔 실행 경로를 대조한다. 모터 종류와 그리퍼 1/2 매핑을 확인한다. 신규 파워트레인 측 어댑터 및 상태 모델을 설계한다.
2. **기존 도구 선택·장착·상세 정보 연결**: `/tool/status` 등 실제 팔 상태를 받아 기존 도구 선택부에 감지 도구를 우선 표시하고, 기존 장착·ID·인터페이스·상세 창을 채운다. 선택 후보와 관측값을 구별한다. 기존 선택 콜백은 화면 기능이며 물리 변경을 자동 실행하지 않는다. 명시 변경 요청은 5단계에 추가한다.
3. **기존 조종 모드·관절 부하·진단 연결**: `/control/mode_status`를 기존 `연동 예정` 영역에 연결한다. 현재 팔 드라이버가 실제 발행하는 피드백을 기준으로 부하·모터·관절 데이터를 기존 표시 영역에 전달한다. `/dynamixel/state` 미발행 경로도 확인하며 없는 온도·전류를 추정하지 않는다. 데이터 손실 시 표시를 지운다.
4. **기존 UI 연결 검증**: 실제 ROS→파워트레인 어댑터→UDP→GTK 경로에서 수신·stale·분리·도구 교체·재연결을 확인한다. 기존 작업 영상·인식 데이터 연결 상태도 점검하되 영상 시스템 재설계는 하지 않는다. 이 시점에 기존 디자인의 연결 결과를 사용자에게 보여준다. 하드웨어 원천이 없으면 격리 ROS 검증과 실기 미검증을 구분한다.
5. **로봇팔 수동조작 탭과 권한·상태 기능**: 기존 스타일의 상단 탭을 추가하고 A1 변경 요청, A2 차단 이유, A3 제어권 요청, A9 FSM, A10 현재 도구 진단을 배치한다. 인증 명령 어댑터와 응답 처리를 함께 구현·검증한다. 기존 화면은 2~3단계에서 연결한 동일 상태를 재사용한다.
6. **그리퍼별 전용 조작 패널**: 단일/듀얼 패널과 듀얼 동기화 표시를 신규 파일로 추가한다. 기존 팔 FSM 인터페이스로 명령·승인·정지 경로를 기능별 검증한다.
7. **키보드 텔레옵**: 원본 TUI 기능 대조표에 따라 축 선택·누름 조그·속도·정지·복귀·home·자세 관리를 구현한다. 기존 팔 제어 경로와 단일 소유권을 확인한 후 연결한다. 탭/포커스/권한 상실의 조그 종료를 검증한다.
8. **로봇팔·도구 캘리브레이션 탭**: 먼저 단일/듀얼 도구 끝점 보정, 다음 팔 기어비·영점·가동범위를 연결한다. 측정·검증·임시 적용·영구 저장을 구분해 기능별 검증한다.
9. **전체 통합 확인**: 두 신규 탭과 기존 UI 연결을 함께 확인하고 영상·주행·복구 기능 회귀와 종료 처리를 검증한다. 마지막 단계는 최초 연결이 아니라 각 단계에서 연결한 기능의 종합 검증이다.

신규 파일 후보: `arm_state.py`, 팔 텔레메트리 어댑터, `arm_panel.py`, `tool_panels.py`, `arm_manual_panel.py`, `arm_keyboard.py`, `arm_calibration_panel.py` 및 각 테스트.
기존 수정 접점 후보: `app.py`, `arm_telemetry.py`, `ros2/src/powertrain_ros/powertrain_ros/arm_console_bridge_node.py`, 필요한 ops 등록부. 변경은 최소 연결부로 제한하며 `extreme-robot`은 수정하지 않는다.
기능 구현 시 `docs/specs/`에 계약 설계를 먼저 기록하고 이 계획의 단계별 결과를 갱신한 뒤 `docs/reports/`에 검증 범위를 남긴다.

## 6. 검증 및 완료 기준

- 최초 수신 시 실제 도구 우선 표시. 수동 후보 선택 중 덮어쓰기 없음. 거부·시간 초과에도 실제 도구 표시는 유지.
- 모드 요청 후 승인 전 구동 불가. 오래된 정상 상태로 조작 활성화 금지.
- 단일↔듀얼 전환 때 올바른 전용 패널과 현재 도구 ID만 표시. 이전 도구 누름 명령·응답 누출 없음.
- 키보드 원본 기능 대조표 완성. 키 해제뿐 아니라 탭 전환·포커스 이탈·팝업·종료·연결 손실 시 조그 종료 검증.
- 팔·도구 보정 기능이 전용 탭에 모이고 임시 적용/영구 저장/미지원이 구별됨.
- 기존 영상 재연결·주행·복구 설정 흐름의 회귀 없음.
- UI 구현 뒤 시스템 Python/GTK 환경에서 콘솔 관련 테스트와 `operator_console.runtime_smoke`, `operator_console.integrated_runtime_smoke`를 실행한다. 새 화면과 입력 경로를 스모크에 포함한다.
- UI/가짜 데이터 통과와 실물 연결·모션 검증을 별도 결과로 기록한다. 계획 작성 완료를 제품 기능 완료로 표현하지 않는다.

## 7. 사용자 검토 포인트

- A11 해석: 듀얼 동기화 정보는 진단에 유지하고 전체 캘리브레이션은 별도 탭에 배치.
- 도구 이름: 우선 내부 실제 타입으로 구분하고 `그리퍼 1/2`의 대응은 기구 종류가 드러나는 이름으로 정리.
- 키보드 기능은 기존 의미를 보존하고, 캘리브레이션 관련 조작은 전용 탭에 배치.
- 청소기 구동 버튼은 이번 선택 범위에 없으므로 정보 표시만 유지.
