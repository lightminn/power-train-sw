## 1. 개편의 한 문장 목표

현재 운영 콘솔에 흩어진 주행·인식·로봇팔·환경 센서 정보를 **실시간 운용 화면과 엔드이펙터 중심으로 재배치**하고, 별도 로봇 상태 화면은 **전원·통신·안전을 묶은 시스템 상태 화면으로 축소**한다.

핵심 원칙은 다음과 같다.

- 시연 중 자주 보는 정보는 `실시간 화면`에 둔다.
- 상세 정보는 항상 펼쳐 놓지 않고 선택형 팝업으로 제공한다.
- 실제 보유한 엔드이펙터만 노출한다.
- 카메라 모델명, 포트, 오도메트리 원본 등 시연에 불필요한 기술 정보는 기본 화면에서 제거한다.
- 화면에 값이 없을 때 임의의 `0`이나 정상 상태를 만들지 않는다.

## 2. 현재 GUI 상태

### 2.1 현재 상위 구조

현재 심사/운용 화면에는 다음 두 탭이 있다.

1. `실시간 화면`
2. `로봇 상태`

환경 센서 전용 상단 탭은 앞선 수정에서 제거되었다. 현재는 `실시간 화면` 우측의 엔드이펙터 선택 영역에서 `환경 센싱 모듈`을 선택하면 별도 팝업으로 환경 센서 상세 화면이 열린다.

### 2.2 현재 엔드이펙터 구현

현재 구현은 다음과 같다.

- 우측 레일에 엔드이펙터 선택 콤보박스가 있다.
- 선택된 엔드이펙터의 용도와 상태를 작은 요약 카드로 표시한다.
- 콤보박스에서 항목을 선택하면 상세 팝업이 자동으로 열린다.
- `환경 센싱 모듈`은 8개 센서 카드가 있는 `EnvironmentSensorDashboard`를 팝업에 표시한다.
- 다른 엔드이펙터는 장착 여부, ID, 인터페이스 등 일반 상세 정보를 표시한다.

이 앞선 수정은 아직 커밋되지 않은 워킹 트리 변경일 수 있으므로 반드시 diff를 확인해야 한다.

### 2.3 환경 센서 데이터 경로

환경 센서 GUI 데이터 경로는 유지해야 한다.

```text
Raspberry Pi 센서 프로그램 JSON
  -> SSH 표준출력
  -> scripts/environment_ssh_bridge.py
  -> UDP 127.0.0.1:5008
  -> LatestEnvironmentTelemetryReceiver
  -> EnvironmentSensorDashboard
```

환경 센서 수신 계약과 SSH 브리지 자체는 이번 UI 정리의 제거 대상이 아니다. 표시 방식만 간소화한다.

## 3. 사용자 원문 요구사항

### 실시간 화면 탭

1. 로그에서 `수준`은 필요 없을 수 있다. 제거하거나 `위험도`처럼 이해하기 쉬운 표현으로 바꾼다.
2. 엔드이펙터 선택 항목을 실제 보유 장비로 줄인다. 현재 보유 범주는 두 종류의 그리퍼, 청소 모듈, 센서 모듈이다.
3. 선택창에서 보이는 엔드이펙터 정보는 간략하게 만들되 현재보다 글씨를 크게 한다.
4. 엔드이펙터를 선택하면 이펙터별 정보를 팝업으로 표시한다. 환경 센서 모듈이 첫 사례다.
5. 환경 센서 팝업은 현재 내용이 너무 많고 정리되지 않았으므로 정보량과 구조를 다시 설계한다.
6. `주요 장치` 영역에서 카메라 모델명과 같은 사양은 필요 없다.

### 로봇 상태 탭

1. 주행 화면에는 불필요한 정보가 많다. 평균 속도만 다른 곳으로 옮기고 주행 세부 화면은 삭제하는 방향을 검토한다. 특히 운용 모드와 오도메트리는 기본 화면에서 필요 없다.
2. 인식 정보는 별도 상태 화면 대신 실시간 화면에 작게 표시하거나 팝업으로 이동한다.
3. 전원 화면은 수빈님이 이전에 작성한 Python 파일 또는 PDIST80B 데이터시트를 바탕으로 정보를 확장한다.
4. 통신과 안전은 독립 화면으로 두기보다 전원 화면과 합쳐 하나의 시스템 상태 화면으로 구성한다.
5. 로봇팔 독립 화면은 필요성이 낮다. 관절 부하와 조종 모드만 실시간 화면의 엔드이펙터 영역으로 이동한다. 엔드이펙터 영역 자체를 `로봇팔 관리` 성격으로 바꾸는 방안도 검토한다.

## 4. 확정된 목표 분류

### 목표 A. 실시간 화면을 운용 중심으로 단순화

실시간 화면에는 시연 중 바로 봐야 하는 정보만 남긴다.

- 카메라 영상
- 현재 평균 속도
- 최신 인식 결과 요약
- 현재 엔드이펙터와 핵심 상태
- 로봇팔 조종 모드와 관절 부하 요약
- 꼭 필요한 시스템 준비/경고 상태
- 간결한 최근 이벤트

다음 정보는 실시간 화면 기본 노출에서 제거하거나 상세 화면으로 내린다.

- 카메라 모델명(`L515`, `D435i`)을 반복하는 문구
- 포트, 전송 방식, 원본 채널 등 기술 사양
- 오도메트리 원본 좌표
- 운용자가 즉시 판단하는 데 필요 없는 진단 문구

### 목표 B. 엔드이펙터 선택지를 실제 장비로 제한

현재 코드의 `END_EFFECTOR_PURPOSES`에는 실제 보유 장비보다 많은 항목이 있다. 최종 UI에는 다음 네 범주만 남긴다.

1. 그리퍼 1
2. 그리퍼 2
3. 청소 모듈
4. 환경 센서 모듈

주의: 두 그리퍼와 청소 모듈의 **정확한 제품/표시 이름은 아직 확정되지 않았다.** 구현 전에 사용자에게 이름을 확인하거나 실제 로봇팔 자료에서 확인해야 한다. 기존 목록의 `범용 그리퍼`, `정밀 핀셋 그리퍼`, `소프트 그리퍼` 중 임의로 두 개를 선택하면 안 된다.

### 목표 C. 엔드이펙터 영역을 로봇팔 관리 허브로 확장

우측 엔드이펙터 영역은 단순 선택 콤보가 아니라 로봇팔과 도구의 핵심 상태를 모으는 영역으로 바꾼다.

메인 요약에서 보여줄 후보 정보:

- 현재 선택/장착 이펙터
- 연결 또는 장착 상태
- 이펙터 핵심 수치 2~4개
- 로봇팔 조종 모드
- 관절 부하 요약
- 상세 보기 동작

기본 글씨는 현재보다 커야 한다. 작은 설명문을 여러 줄 배치하는 대신 제목, 큰 핵심값, 한 줄 상태를 우선한다.

### 목표 D. 이펙터별 팝업 패턴 통일

모든 엔드이펙터는 같은 상호작용 구조를 사용한다.

```text
메인 화면의 엔드이펙터 선택/요약
  -> 항목 선택 또는 상세 보기
  -> 해당 이펙터 전용 비모달 팝업
```

팝업에는 해당 이펙터에 실제로 필요한 정보만 표시한다.

- 그리퍼: 장착/연결, 조종 모드, 관절 부하, 도구에 필요한 실제 상태
- 청소 모듈: 연결/동작 상태와 실제 제공 가능한 핵심 값
- 환경 센서 모듈: 환경 측정값과 위험 상태 요약

없는 텔레메트리는 만들지 않고 `정보 없음` 또는 `연동 예정`으로 표시한다.

### 목표 E. 환경 센서 팝업 재설계

현재 팝업의 문제:

- 8개 카드가 같은 중요도로 보인다.
- 카드마다 추세 그래프, 상태, 그룹 칩, 출처 메모가 있어 정보량이 과하다.
- 중요한 위험 정보와 기술 설명의 시각적 우선순위가 섞여 있다.
- 메인 요약 글씨가 작다.

목표 구조:

1. 상단: 전체 센서 연결 상태와 종합 상태
2. 핵심 환경: 온도, 습도, 기압
3. 공기질: eCO2, TVOC
4. 위험 감지: CO, LPG, 불꽃
5. 하단 또는 접기 영역: 교정 상태, 출처, 마지막 갱신 등 기술 정보

표시 원칙:

- 값과 단위는 크게 표시한다.
- `정상 / 주의 / 위험 / 데이터 없음`을 분명히 구분한다.
- CO/LPG는 기준가스 교정 전이므로 절대 안전 판정처럼 표현하지 않는다.
- eCO2는 NDIR 방식의 실제 CO2가 아니라 SGP30 추정값임을 과도하지 않게 표시한다.
- 60초 추세 그래프를 모두 유지할지는 미정이다. 유지하더라도 핵심 센서에만 제한한다.
- UDP 포트, sequence, source 문자열은 기본 화면에서 숨기고 진단 영역으로 이동한다.

### 목표 F. 로봇 상태를 시스템 상태 중심으로 재편

기존의 주행·인식·전원·통신·로봇팔·안전 개별 상세 화면을 그대로 유지하지 않는다.

제거 또는 이동:

- 주행 상세: 제거 후보
- 평균 속도: 실시간 화면으로 이동
- 운용 모드·오도메트리: 기본 UI에서 제거
- 인식: 실시간 화면의 작은 요약 또는 팝업으로 이동
- 로봇팔: 독립 화면 제거 후보
- 관절 부하·조종 모드: 엔드이펙터/로봇팔 관리 영역으로 이동

남길 핵심:

- 전원
- 통신 상태
- 안전 상태

이 세 영역은 `시스템 상태` 또는 이와 유사한 하나의 통합 화면으로 묶는 방향이다.

### 목표 G. 전원 정보 확장

현재 전원 화면보다 PDIST80B의 실제 운용 정보를 더 많이 표시해야 한다.

구현 전에 확인할 자료:

- 수빈님이 이전에 작성한 PDIST80B 관련 Python 파일
- `/home/kimseon/문서/카카오톡 받은 파일/분배/pdist80b_26.07.01.py`
- `/home/kimseon/다운로드/전원분배보드PDIST.pdf`
- 필요하면 `/home/kimseon/다운로드/ilovepdf_split-range/`의 분할 PDF
- 현재 `operator_console/telemetry.py`와 `operator_console/status_view.py`가 이미 해석하는 PDIST 필드

전원 확장 시 후보 정보:

- 배터리 전압, 전류, 전력
- SOC
- 충전/방전 상태
- 보호 플래그와 경고
- 개별 출력 또는 분배 채널 상태(실제 프로토콜에 존재할 때만)
- RS485/PDIST 통신 상태
- 마지막 정상 갱신
- 통신 단절과 계측 이상 구분

데이터시트에 있는 값이라고 해서 현재 송신 텔레메트리에 없는 값을 GUI가 직접 장치에서 읽으면 안 된다. 데이터 소유자는 기존 전원/차체 텔레메트리 송신 경로여야 하며 GUI는 계속 RX-only를 유지한다.

### 목표 H. 로그 문구와 구조 단순화

현재 이벤트 로그의 `수준`은 사용자에게 의미가 약하다.

가능한 방향:

- `수준` 열을 완전히 제거한다.
- 또는 `위험도`/`상태`로 변경한다.
- 기술 로그 레벨 대신 `정보 / 확인 필요 / 위험`처럼 운용 의미가 있는 한국어 상태를 사용한다.

로그 기본 화면은 시간과 핵심 메시지를 우선하며, 모듈명이나 원본 기술 메시지는 상세/진단 영역으로 내린다.

## 5. 목표 정보 구조 초안

### 5.1 실시간 화면

```text
상단
  - 전체 연결/전원/안전 요약
  - 긴급 정지

중앙
  - 주 영상
  - 작은 보조 영상
  - 인식 결과 요약 또는 인식 상세 팝업 진입

우측
  - 현재 임무 핵심 상태
  - 평균 속도
  - 로봇팔·엔드이펙터 관리
      - 실제 이펙터 4종 선택
      - 큰 글씨의 핵심 상태
      - 조종 모드
      - 관절 부하
      - 이펙터별 상세 팝업

하단
  - 간소화한 최근 이벤트
```

### 5.2 시스템 상태 화면

```text
전원
  - PDIST80B 핵심 계측과 보호 상태

통신
  - 로봇/전원 텔레메트리 수신 상태
  - 필요한 링크 상태만 표시

안전
  - 비상정지, 장애물 안전, 주요 보호 상태

고급 진단
  - 원본 플래그, 채널, 포트, 마지막 수신 등
  - 기본적으로 접힘
```

탭 이름은 `로봇 상태`를 유지할 수도 있고 `시스템 상태`로 바꿀 수도 있다. 아직 확정되지 않았다.

## 6. 미정 사항

다음 항목은 구현 전에 결정해야 한다.

1. 실제 보유한 두 그리퍼의 정확한 표시 이름
2. 청소 모듈의 정확한 표시 이름
3. 엔드이펙터 영역 제목을 `엔드이펙터`, `로봇팔 관리`, `로봇팔·도구` 중 무엇으로 할지

7. 로그의 `수준`을 삭제할지 `위험도`로 바꿀지

## 9. 완료 조건

### 실시간 화면

- 실제 보유한 네 종류의 엔드이펙터만 선택할 수 있다.
- 엔드이펙터 요약이 현재보다 크고 한눈에 읽힌다.
- 각 이펙터는 동일한 방식으로 상세 팝업을 연다.
- 환경 센서 팝업은 핵심값과 위험 상태의 우선순위가 명확하다.
- 평균 속도와 인식 결과를 실시간 화면에서 확인할 수 있다.
- 카메라 모델명과 불필요한 기술 사양이 주요 장치 영역을 차지하지 않는다.
- 이벤트 로그에서 기술 레벨보다 운용 메시지가 우선한다.

### 시스템 상태

- 전원·통신·안전이 하나의 일관된 화면에서 보인다.
- PDIST80B의 실제 제공 정보가 기존보다 충실히 표시된다.
- 주행·인식·로봇팔의 중복 상세 화면이 제거되거나 사용자에게 노출되지 않는다.
- 값이 없을 때 `0`이나 `정상`을 만들지 않고 `정보 없음`으로 표시한다.

### 기술 검증

- `/usr/bin/python3 -m py_compile operator_console/app.py operator_console/status_view.py` 통과
- 관련 순수 로직 pytest 통과
- `/usr/bin/python3 -m operator_console.runtime_smoke` 통과
- 환경 센서 SSH 브리지로 실제 `UDP :5008` 수신 확인
- 센서 데이터 중단 후 STALE 전환 확인
- 1600×900과 1920×1080에서 글자 잘림과 우측 레일 넘침 확인
- 팝업을 여러 번 열고 닫아도 수신기와 GTK 위젯이 중복 생성되지 않음

## 10. 변경하면 안 되는 안전 원칙

- GUI 관측 경로는 RX-only를 유지한다.
- GUI가 USB, CAN 또는 I2C 장치를 직접 열어 누락된 값을 채우면 안 된다.
- 조작 명령은 기존 token-gated ops 경로 외에 새로 만들지 않는다.
- 센서값, 전원값, 장착 상태를 추정해서 정상처럼 표시하지 않는다.
- 환경 센서 CO/LPG 추정 ppm을 교정된 안전 판정으로 표현하지 않는다.
- 비상정지 동작과 인증 경로를 UI 정리 과정에서 약화하지 않는다.
- 시스템 Python(`/usr/bin/python3`)을 사용한다. Conda Python에는 GTK `gi`가 없을 수 있다.

## 13. 2026-09-02 구현 결과

- 실시간 화면에 평균 구동 속도, 최신 인식, 대상 거리, 로봇팔 조종 모드
  연동 상태, 관절 부하 요약을 배치했다.
- 기본 화면의 `L515`/`D435i` 모델명은 `전방 화면`/`작업 화면`으로 바꿨다.
- 엔드이펙터는 확인된 네 범주인 `그리퍼 1`, `그리퍼 2`, `청소 모듈`,
  `환경 센서 모듈`만 노출한다. 실제 자료에서 두 번째 그리퍼와 청소 모듈의
  제품명이 확인되지 않아 제품명을 임의로 만들지 않았다.
- 우측 영역 제목은 `로봇팔 · 도구`로 확정했고, 모든 도구는 같은 비모달
  상세 팝업 패턴을 사용한다.
- 환경 센서 팝업은 `핵심 환경 / 공기질 / 위험 감지` 세 그룹으로 재구성했다.
  추세는 온도, eCO₂, 불꽃만 노출하며 포트·sequence·source는 접힌 진단에 둔다.
  상태는 `정상 / 주의 / 위험 / 데이터 없음`을 분리한다. 불꽃 감지는 `위험`,
  교정 전 CO/LPG는 `주의 · 교정 전`, 오래된 값은 `갱신 지연`으로 표시하며,
  미수신 값을 오류나 정상으로 추정하지 않는다.
- 이벤트의 `수준` 열을 제거하고 필터 문구를 `위험 / 확인 필요 / 정보`로
  바꿨다. 원본 레벨과 모듈명은 개발자 상세에만 남긴다.
- `로봇 상태` 탭은 `시스템 상태`로 바꾸고 전원·통신·안전 세 영역만 통합
  표시한다. 주행 좌표/모드, 별도 인식 및 로봇팔 상세 페이지는 노출하지 않는다.
- PDIST80B는 현재 UDP 계약에 있는 전압, 방전/충전전류, 전력, SOC,
  충전·외부제어 상태, 보호 플래그, RS485 상태만 표시한다. 데이터시트에는
  있으나 텔레메트리에 없는 전압 PID 편차, 알람 누적 횟수, 분배 출력 상태는
  추정하지 않는다.
- 검증: 264개 operator-console 테스트, 문법 검사, 5채널 LIVE→STALE
  런타임 스모크, 1600×900/1920×1080 위젯 할당 확인을 통과했다.

## 14. 2026-09-04 후속 감사 및 실센서 재검증

- 미수신 `power_w`를 전압×전류로 합성하던 표시를 제거했다. 전력값과
  충전·제어 플래그가 계약에 없으면 각각 `정보 없음`으로 유지한다.
- PDIST80B 보호 플래그가 없으면 전원 카드를 정상으로 승격하지 않는다.
- 통신 카드의 정상 판정은 로봇·전원·인식 텔레메트리, 전방·작업 영상,
  조작 채널이 모두 준비된 경우로 제한했다.
- US-100 활성 상태나 필수 로봇팔 온도 데이터가 없으면 안전 카드를
  정상으로 추정하지 않는다. 비상정지는 항상 최우선 위험 상태로 유지한다.
- 기본 시스템 화면의 `LIVE`/`VALID`/`UNAVAILABLE` 및 RS485 PID 같은
  기술 문자열을 운용자용 한국어 상태로 바꾸고, 원본은 접힌 진단에 남겼다.
- 환경 센서 일부 필드가 없을 때 메인 요약에 `None`이 노출되지 않게 했고,
  1260×820 팝업에서 8개 핵심 카드가 스크롤 없이 보이도록 세로 밀도를 조정했다.
- 공개 이벤트에서 `L515`/`D435i` 모델명을 각각 `전방 화면`/`작업 화면`으로
  치환했다. 원본 소스명은 개발자 상세에서만 확인할 수 있다.
- 실제 GTK 캡처 도구가 환경 채널용 임시 포트와 환경 팝업을 지원하도록 갱신했다.
- 검증: 272개 operator-console 테스트, 신규 게이트 음성 대조 4종, 문법 검사,
  5채널 LIVE→STALE 런타임 스모크, 1600×900 실시간 화면, 1920×1080 시스템
  화면, 1260×820 환경 팝업 캡처를 통과했다. Raspberry Pi SSH 브리지의 실제
  UDP `:5008` 패킷도 수정된 GUI에서 `LIVE`로 재수신했다.
