# MKS CAN 신뢰성 수정 설계

사용자가 2026-09-09 제안한 해결 방안에 `진행해`로 실행을 승인했다.
범위는 원격주행 CAN 통신이며 자율주행, US-100/L515 연결 검증은 제외한다.

## 계약

1. Jetson의 `DriveOdriveCan.tick()`와 `poll_feedback()`는 같은 제한된 조회 경로를 쓴다.
   50 Hz 차체 tick에서 6축 encoder 조회를 공유하는 3개 논리 주기로 나눠 동시에 최대 2축을
   조회한다. 각 축 정상 조회 간격은 60 ms이며, 200 ms freshness 판정은 유지한다.
   Iq는 축별 약 1 Hz로 분산한다. 장시간 지연 후 누적 조회를 몰아서 보내지 않는다.
   속도 명령은 기존 제어 tick마다 보내며 조회 제한에 종속시키지 않는다.
   절대시간의 나머지와 정확히 일치해야 조회하는 방식은 사용하지 않는다. 15/15/30 ms
   지터에서도 논리 주기 0→1→2를 차례로 진행하고, 같은 주기의 추가 호출은 중복하지 않는다.
   단일 축 독립 사용은 지난 deadline을 처리하고 다음 미래 deadline으로 넘긴다.
2. MKS 제조사 ZIP SHA256
   `1c9ff347f997bbbf8cb693cdb44d93fe6f6ef992aefde60b6a65b0e1fa25a777`
   을 고정하고 패치·빌드·시험 경로를 저장소에서 재현 가능하게 제공한다.
   실제 unreleased 바이너리와 배포 ZIP의 동일성은 확인되지 않았다.
3. CAN 송신 슬롯 확인과 HAL 송신 등록을 원자화한다. 높은 우선순위 모터 루프를
   블로킹 mutex나 HAL 재초기화 대기로 묶지 않는다. 일시적 슬롯 부족은 유한한 drop으로
   처리하고 계수한다. 오류 기록, 오류 루프의 유한 대기, CAN 재초기화의 송신 배제를 구현한다.
4. CAN 오류 복구 시 양축을 오류 래치·IDLE로 전환하고 과거 명령을 제거한다.
   복구가 운전 재개를 의미하지 않는다. 명시적 오류 해제와 새 운전 시작이 필요하다.
5. 통신 watchdog은 조회 패킷으로 갱신하지 않는다. 길이/RTR/유한값 검사를 통과한
   새 제어 setpoint만 갱신한다. 300 ms는 벤치 검증 후보값이며 생산 확정값이 아니다.
   USB 운용과 캘리 경로에 대한 적용 조건을 문서화한다.
6. 실제 flash 전 대상 serial, 전체 설정·캘리 값, 원본 firmware/NVM 복원 경로,
   보드 호환성과 빌드·소스 시험 결과를 확보한다. 복원 경로가 없으면 firmware 쓰기를
   진행하지 않고, 가능한 소프트웨어 작업과 배포를 완료하며 미충족 조건을 보고한다.
7. 사용자가 **모든 바퀴가 땅에 닿은 부하 상태**, 안전 환경과 전원 차단 준비를 확인했다.
   이번 실물 시험의 허용 범위는 **구동 모터축 1회전 이내**다. 바퀴 1회전으로 확대하지 않는다.
   먼저 0속도 통신 단절·복구를 시험하고, 이후 작은 위치 목표와 독립 정지 제한을 적용한다.
   출력 차단과 실제 제동거리 인수를 구분한다. 통신 복구만으로 완료를 선언하지 않는다.

## 검증

- 원본의 TX 경합·오류 후 영구 무응답·조회 watchdog 갱신을 실패 시험으로 고정한다.
- 수정본에 같은 선점/오류를 주입해 후속 통신, 정지 래치, 유한 복구와 입력 검증을 확인한다.
- 실제 MKS firmware를 빌드한다. 호스트 HAL stub 시험과 MCU 실행 증거를 구분한다.
- Jetson 실제 드라이버 경로의 6축 조회 시험을 수행하고 raw CAN으로 송신 범위·간격·응답을 대조한다.
- 단일 보드 검증 후 나머지 보드에 확대한다. 전원 반복·통신 단절·실주행은 각각 별도 판정한다.
