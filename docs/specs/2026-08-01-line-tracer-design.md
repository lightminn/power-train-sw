# 코리도 인증을 버리고 중심선 추종으로 — 설계

작성 2026-08-01. 대상 `powertrain_autonomy` 판단부.
근거: 실코스 599프레임 계기 측정(`runs/sweep_cline.log`, `sweep_cline2.log`),
120런 373,500틱 사유 집계, band 모델 8패밀리 캠페인.

## 1. 왜 바꾸는가

측정된 병리는 하나다 — **시스템이 조향하는 대신 정지한다.**

```
전체 틱의 88.3% CONTROLLED_HOLD
기각 사유의 88% erosion_empty
실코스 60초 동안 추정이 나온 프레임 8 / 599
```

`clearance_low` 가 정지 사유의 85% 지만 이는 여유 부족이 아니다. `_reject` 가
clearance 를 0 으로 놓기 때문에 기각된 프레임마다 `path_unavailable`·`low_confidence`
와 **정확히 같은 수**로 찍힌다. 수락된 8프레임에서 실제 발행값은 우측 여유 0.1055 m,
좌측 0.5305~0.6305 m, 오프셋 +0.2125~+0.2625 로 **여유는 넉넉하고 조향 신호도 깨끗하다.**

즉 추정기는 답을 낼 때는 잘 낸다. 98.5% 의 시간 동안 **답하기를 거부**한다.

캠페인의 `edge_overrun 0` 도 안전이 아니었다. narrow_curve 기준선은 완주 0.023~0.028
— 안 움직여서 이탈을 못 한 것이다. band 모델로 완주 0.229 가 되자 시드 하나에서
`edge_overrun 1` 이 나왔다.

## 2. 계기는 충분한가 — 측정

게이트를 전혀 걸지 않고 매 프레임 중심선을 뽑아 599프레임을 기록했다.

```
중심선 산출     599 / 599          (게이트 있는 현재 8 / 599)
월드 중심점 산포 sd 0.044~0.052 m   (로버는 60초에 0.238 m 만 이동)
편측 여유 예산   0.081 m (평지) / 0.021 m (능선)
```

**평지 예산 안이다.** 능선은 아니다 — §6.

### 2.1 어떤 행이 중심을 말할 자격이 있는가

계획창 안에 support 폭이 0.400 m 인 행이 있다(로버 0.789 m). 그런 행의 "support 중심"은
트랙 중심이 아니라 **관측 구멍의 중심**이다. 네 가지 추정기를 같은 런에서 비교했다.

| 추정기 | 적합 잔차 med | 월드 sd | \|Δa\| max |
|---|---|---|---|
| A 전 행 lstsq | 0.468 | 0.052 | 0.187 |
| **F 폭≥로버 lstsq** | **0.108** | 0.070 | 0.788 |
| M 폭필터 median | 0.325 | **0.044** | **0.100** |
| W 폭가중 lstsq | 0.727 | 0.051 | 0.540 |

폭 필터가 잔차를 **4.3배** 줄인다. 그러나 F 단독은 프레임 간 0.788 m 점프가 있어 못 쓴다.
M 은 가장 안정적이지만 상수라 기울기를 못 잡는다(기여 행들의 기울기 실측 bF med 0.30).

**결론: 폭 필터 + 강건 적합 + 기존 시간 저역필터의 조합.** 넷 중 어느 하나도 아니다.

이 규칙은 오늘 에지에서 배운 것과 같다. 에지에서는 "관측이 멈춘 행이 트랙 에지를
말했고", 중심에서는 "로버가 못 들어가는 폭의 행이 중심을 말한다".

## 3. 설계

### 3.1 중심선

계획창(`path_x_range_m`)의 각 행에서 선택된 support run 을 `[r_i, l_i]` 라 할 때,

- **기여 행 조건**: `l_i - r_i >= 2 * footprint_half`. 로버가 들어갈 수 없는 폭의 행은
  중심을 말할 자격이 없다.
- 행 중심 `c_i = 0.5 * (r_i + l_i)`.
- `centre(x) = a + b*x` 를 기여 행으로 최소제곱 적합하고, 잔차가
  `2 * grid_resolution_m` 을 넘는 행을 한 번 잘라내고 재적합한다(T3 의 `fit_band` 와
  같은 절차 — 검증된 기계를 재사용한다).
- 기여 행이 2개 미만이면 적합하지 않는다. 그 프레임은 `path_available=False`.
  실측에서 이런 프레임은 599 중 0개였다(기여 행 수 median 25, 최소 24).

`path_offset` 은 기여 행에서 평가한 `centre(x_i)` 의 median 으로 둔다 —
현재 의미(선택 행 중심의 median)와 같게 유지한다. `heading = atan(b)`.

기존 `path_estimate_tau_s` 저역필터를 offset·heading 에 그대로 적용한다(F 의 0.788 m
점프를 잡는 것이 이 필터의 역할이다).

### 3.2 조향

바꾸지 않는다. `ω = kp_heading*heading + kp_offset*offset`, `kd_yaw` 감쇠 포함
(clothoid 수정분). 속도는 프로파일의 `max_speed`.

### 3.3 안전 게이트 — 하나

계획창 행 중 support 가 로버 자기 발자국을 덮는 행이 **하나도 없으면 정지**한다.
덮는다 = `r_i <= -footprint_half` 이고 `l_i >= +footprint_half` (body frame).

이것이 "바퀴가 관측된 support 밖에 있다"의 직접 표현이며, 낙하 방지의 마지막 줄이다.
실측 기여 행 수 median 25 이므로 정상 주행에서 오탐하지 않는다.

차량 한계(pitch/roll 전복 방지)는 코리도 안전이 아니라 차량 사양이므로 유지한다.

## 4. 삭제 목록

```
erosion 예산 게이트 (footprint_uncertainty_m · odometry_residual · carry margin)
clearance_hold_m / clearance_full_m 속도 램프와 clearance_low 정지
choke (inner_columns) 와 obstacle 게이트
  → 장애물 셀은 support 가 아니므로 중심선 추출이 자연히 피해가고,
    못 지나가면 §3.3 게이트가 잡는다. 게이트가 아니라 지형으로 다룬다.
인증/미인증 에지 구분 전체
  *_edge_unverified · *_clearance_unverified · *_drop_boundary · right/left_observed
재중앙정렬 창과 4개 knob (speed · slack · timeout · cooldown)
lateral reference carry (`_transport_lateral_reference` 및 2 knob)
T3 의 band 적합 기계 (measurement/bound 이분법) — 중심선이 대체한다
```

코리도 **경계 두 개**를 추정하지 않으므로, 2026-07-30~31 에 싸운 인증/관측한계/
median/widest 문제가 통째로 사라진다. 추정하는 것은 **중심선 하나**다.

## 5. 보존해야 하는 성질

1. 관측된 support 를 지면이 아니라고 주장하지 않는다.
2. 로버 발자국을 덮는 support 행이 없으면 정지한다(§3.3).
3. 차량 자세 한계(pitch/roll)는 그대로 강제한다.
4. US-100 은 독립 하드웨어 층으로 불변.

## 6. 능선은 이 설계로 풀리지 않는다 — 분리한다

```
격자 해상도 grid_resolution_m = 0.05  →  어떤 추정도 ±0.025 아래로 못 간다
능선 편측 여유 0.021
```

**능선 예산이 격자 한 칸의 절반이다.** 알고리즘이 아니라 계기 해상도의 문제이므로
이 설계의 성공/실패와 무관하게 남는다. 선택지는 근거리 격자 세분화 / 능선 구간
저속·개루프 / 위험 수용이며, 별도 판단으로 다룬다.

## 7. 판정

단일 실행으로 판정하지 않는다.

- 8패밀리 + `narrow_curve` × 시드 3: `fail_open 0` 유지가 하드 게이트.
  `edge_overrun` 은 기준선이 마비로 0 을 얻었으므로 **완주율과 함께** 읽는다 —
  완주가 늘면서 edge_overrun 이 늘면 §3.3 게이트를 조사한다.
- 실코스 6스폰 × 두 팔(현행 HEAD vs 라인트레이서): 거리 중앙값·스프레드.
- 계기 재측정: 중심선 산출률과 월드 산포가 §2 수치를 유지하는지.
