# GUI 차체 3D 표시

요청: 첨부 JETIN CAD 모델을 콘솔에서 보고, 측정 관절각에 맞춰 자세를 표시하며 바퀴를 눌러 기존 모터 상태를 확인한다.

GTK 콘솔의 기존 `협조구동 → 6륜 제어 상태` 카드에 CAD 뷰를 넣는다. 별도 차체 형상 페이지를 만들지 않는다(사용자 위치 정정 반영). 네이티브 WebKitGTK 4.1에 로컬 Three.js와 표시용 메시를 넣는다. 관절의 부모/자식, 피벗, 회전축은 첨부 URDF를 따른다. 자산은 디스크에 저장하고 네트워크 다운로드 없이 열린다. 표시 위젯에는 CAN/USB/ops 연결을 주지 않는다.

바퀴 상태는 기존 `TelemetrySnapshot.wheel_statuses`를 사용한다. IMU roll/pitch를 루트에 적용하고 조향각을 네 조향 관절에 적용한다. 바퀴 회전은 측정 속도 적분의 시각화이며 절대 엔코더 위치로 표기하지 않는다.

로커·보기에는 선택 필드 `suspension_joints_rad`를 받는다. 키는 `ml_rocker_joint`, `mr_rocker_joint`, `bl_bogie_joint`, `br_bogie_joint`이며 값은 보정된 rad 각도다. 함께 전송하는 `suspension_age_ms`는 패킷 생성 시점의 원본 센서 표본 나이다. 표본 나이와 수신 후 경과 시간을 합쳐 1초를 넘거나 나이 필드가 없으면 측정각을 사용하지 않는다. 실물 센서 드라이버·송신기 연결은 이번 범위에 포함하지 않는다.

미수신·오래된 데이터는 명시적으로 표시하고 마지막/기준 자세를 유지한다. 미수신 각도를 0도 측정값으로 취급하지 않는다. 오래된 전류를 숨기고 바퀴 회전을 멈춘다. 모델의 디퍼렌셜 폐루프 제약 해석은 별도 작업이다.

검증은 기존 GUI 검사, 필드 유효성/신선도 검사, 실제 GUI의 격리 UDP 수신→관절 변환→바퀴 팝업→단절 전이, 실사용 데스크톱 기동으로 한다.

## 경량 표시 및 가독성 요구 반영

기본 표시는 원본 CAD 메시 대신 URDF 관절 위치·회전축을 따르는 단순 차체·로커·보기·6개 바퀴·모터 형상으로 한다. 줌·팬은 없애고 고정 높이의 360° 회전만 제공한다. 움직임은 최대20fps, 정지 상태는 변경 시에만 그린다. Noto Sans CJK KR와 기본14px 글씨를 사용하고 협조구동 기술 상세·중복 지표는 숨긴다. 바퀴 팝업은 상태·전류(A)·속도(rpm)·조향각만 표시한다.

사용자 후속 요청에 따라 둥근 파이프·차체 덮개/패널·조향부·바퀴 트레드/허브로 원래 형상의 특징을 조금 복원한다. 삼각형1만 개 미만과 CAD 메시 미사용, 기존 회전/갱신 정책을 유지한다. 팝업 상태는 정상·오류·갱신 지연·미연결의4종이며, 정상은 구동 활성 여부를 뜻하지 않는다.

360° 회전 시 반대쪽이 다른 재질처럼 보이지 않도록 조명은 카메라를 따라가는 주/보조광과 주변광을 쓴다. 반구광은 모델의 Z-up에 맞춘다. 원통은 기본 vertex normal로 부드럽게 표현하고, 부품의 색과 모터 상태색은 회전과 무관하게 유지한다.

## 원본 부품 형태 복원

추가 디테일 요청을 반영해 도형으로 재구성한 형상을 원본 CAD에서 만든 표시용 LOD로 교체한다. 차체·로커·보기·조향부·바퀴·연결 부품은 각 원본 visual과 URDF 변환을 사용하며 로봇팔/도구는 계속 제외한다. 원본 참조 메시를 보존하고 별도 display-meshes에 제한된 정밀도/용량의 메시를 저장한다. 회전·조명·갱신 제한·더미 움직임·팝업 정책은 유지한다. 형상과 실제 GUI 렌더링 성능을 확인한 후 완료한다.

최종 미관 조정은 현재 CAD 부품 형상/관절을 유지하고 표시 면의 작은 삼각형 이음을45° 임계 법선 보간으로 다듬는다. 큰 패널·브래킷 모서리는 유지한다. 줌/팬은 계속 비활성으로 두고 휠 양방향·핀치 입력에서도 확대/축소되지 않음을 확인한다.

이번 미관 정리에서는6mm 미만의 작은 독립 부품을 표시에서 제외한다. 카메라 최소/최대 거리를 같게 고정하고 3D 캔버스 휠 기본 동작을 막아 확대·축소를 차단한다. 큰 부품 형상/관절 계층과 모터 상태는 유지한다.
