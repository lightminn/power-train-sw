# PR #12 통합 콘솔 로봇팔 조작 기능 명세

사용자가 GUI라고 지칭하는 화면은 `operator_console`의 PR #12 통합 운용 콘솔이다.
Qt `robot_manual_gui`는 이번 조작 화면으로 사용하지 않는다.

> **개발 원칙.** 이 문서의 기능은 콘솔 위에 이미 쌓아 둔 것이다. 파워트레인 GUI가 갱신되면
> 새로 만들지 않고 **이 기능 위에서** 이어 개발하며, 아래 §3 회귀 점검표를 매번 통과시킨다.

## 1. 기본 동작 (PR #12, 벤치 확장 OFF)

- USB 1 Mbps, XL430 ID16 = 5축, ID1 = 볼락. 1~4축 기존 캘리브레이션은 변경하지 않는다.
- 2026-10-17 노트북 시험 기준: 5축 0° = 2525 tick, 볼락 LOCKED = 3051 tick.
- 명시적 `manual_coupling_lock=true` + FULL_ROBOT + MANUAL에서만 로컬 시험을 제공한다.
  기본값 false와 기존 END_EFFECTOR_ONLY 게이트는 유지한다.
- 통합 콘솔 → 인증 ops → ROS 브리지 → 단일 USB 소유자 → 실제 피드백으로 연결한다.
- 로컬 조그는 5축만 허용한다. 갱신당 최대12 tick(1.0546875°), 영점±114 tick
  (±10.01953125°)로 제한한다. 명령의 단조시각 만료는 1초 이내여야 하며 콘솔 TTL은0.6초다.
  수신 중단·MANUAL 상실·잠금 준비 상실 시 현재 위치를 홀드한다.
- 단조시각 계약은 **같은 호스트와 Docker 컨테이너 사이 전용**이다. 노트북 GUI→Jetson
  원격 조그는 인수 범위가 아니다(GUI 프로세스는 Jetson에서 돌고 화면만 X11로 넘긴다).
- 볼락 목표는256 tick(22.5°)이며 위치 허용오차는 기본4 tick(0.3515625°)이다.
  활성화는 현재 위치를 먼저 동기화하며, 그 인덱스 안의4 tick 이하 오차만 정착시킨다.
  다른 인덱스로 자동 이동하지 않는다. 팔 조그 해제·정지 확인 전 잠금 전환은 거부한다.
- STOP은5축과 잠금 토크OFF, 조그 버튼을 놓으면5축 현재 위치 홀드다.
  재활성화는 잠금 준비 후 현재 위치를 동기화한다.
- 결합 센서는 없다. LOCKED/UNLOCKED는 엔코더 판정이며 실제 결합 확인이 아니다.

모든 확장은 브리지 파라미터 또는 환경변수로만 켜진다. 끄면 §1 동작 그대로다.
세션 설정 정본은 `config/local_arm_bench_teleop.yaml`, 저장 자세는
`config/local_arm_poses.json`, 볼락 기록 위치는 `config/local_arm_lock_points.json`이다.

### 2.2 키보드 텔레옵

- 축 선택: 숫자 1~5 / 숫자패드 1~5(NumLock 무관) / 축 버튼. 6번은 그리퍼 도구가 있을 때만.
- ↑ / W = + 방향, ↓ / S = − 방향, **누르는 동안만** 이동한다.
  콘솔이 0.2초마다 갱신하고 브리지는 매 갱신 `현재 위치 + 스텝`만 목표로 쓰므로 목표가
  한 스텝 이상 앞서지 않는다. 놓거나 0.6초 갱신이 끊기면 현재 위치 홀드.
- X11 자동반복의 떼기→누르기 쌍은 120ms 유예로 하나의 누름으로 합친다.
- 키는 `로봇팔 수동조작` 탭이 보이고 창에 포커스가 있을 때만 받는다(입력칸 포커스 제외).
  `app.py`가 `ArmManualTab.attach_keys(window)`를 호출해야 한다.
- **관절 제한 토글**: ON이면 1~4축은 `joint_limits.py`, 5축은 영점±114 tick. 범위 밖으로
  **더 나가는 방향만** 막고 범위 밖에서 안쪽으로는 움직인다(경계로 끌려오지 않음).
- **전류 트립 토글**: ON이면 갱신마다 전류/부하를 읽어 문턱 초과 시 홀드(토크는 유지).
- 정지(Space)는 기존 의미(5축·잠금 토크OFF)다. 복귀(T)로 되살린다.

### 2.3 자세 관리

- 저장 대상은 **1~4축**이다. 5축·그리퍼는 원 텔레옵과 같이 제외한다.
- `현재 자세 저장`: 이름 입력 후 현재 각도를 저장한다(이름은 소문자로 정규화).
- `선택 자세로 이동` / `home`(H): 저장 자세로 이동한다. `home`은 이름이 `home`인 자세.
  - 관절 제한 ON이고 저장 자세가 범위 밖이면 **잘라서 가지 않고 이동 전체를 거부**한다.
  - 축별 속도·지연은 2.1 표를 따른다(2축 최우선 ≈19.5°/s, 4축 1초 뒤 ≈15°/s).
  - 정지·새 조그·MANUAL 상실·E-stop·전류 트립(축 출발 0.5초 뒤부터) 시 전 축 홀드.
  - 도착(±20 tick) 또는 홀드 시 조그 프로파일로 되돌린다.
- `자세 자유 지정`: 1~4축 토크 OFF(손으로 자세 잡기). **팔을 받친 뒤 누른다.**
- `자유 지정 해제`: 현재 위치를 목표로 맞춘 뒤 1~4축 토크 ON.
- 자유 지정·해제는 쓰기 가능한 `MANUAL` + `FULL_ROBOT`, 비상정지 없음·조그 없음일 때만 허용한다.
  해제 시 위치를 읽은 뒤에도 같은 조건을 재확인하고 토크를 켠다.
- 예약·진행 중인 자세 이동이 있으면 볼락 조작 요청만 거부한다. 반대로 볼락 목표가 남아
  실제 이동 중일 때는 새 자세 이동·자유 지정 요청만 거부하며, 완료 후 다시 요청할 수 있다.
  거부된 요청으로 기존 자세 이동을 홀드하지 않는다. 이동 명령 쓰기 실패 시 홀드는 유지한다.
- 2026-10-23 사용자 지시: 자세 이동에 볼락의 잠김·준비 상태 게이트는 추가하지 않는다.
  위 동시 실행 방지는 볼락의 실제 이동 목표 유무만 검사하며 속도·가속도·축별 지연은 유지한다.
- 거부 사유는 GUI가 아니라 브리지 로그(`local pose rejected/held`)에 남는다.

### 2.4 ops 액션 (브로커 `ops_contract.ACTIONS`, 콘솔 `registered_actions`)

콘솔의 액션은 세 곳이 모두 맞아야 나간다: `arm_ops/contract.py`(파라미터 명세·설명),
`ops_contract.ACTIONS`(브로커), `app.py`의 `registered_actions`(콘솔 게이트).

### 2.5 볼락 2점 방식

- `현재 위치를 결합 영점으로` = 잠김 위치 기록, `현재 위치를 분리 영점으로` = 열림 위치 기록.
  토크 ON/OFF 무관. 두 기록이 ±40 tick 안이면 새 기록만 남긴다.
- 상태: 잠김 ±20 = LOCKED, 열림 ±20 = UNLOCKED, 그 밖 = BETWEEN(UNKNOWN 아님).
- `도구 결합`/`도구 해제`는 항상 활성이다. 기록이 있으면 그 절대 위치로, 없으면 현재 위치에서
  22.5°(256 tick) 회전한다(0~4095를 넘으면 반대 방향). 토크 OFF면 자동 활성화.
- `잠금 모터 활성화` / `잠금 모터 비활성화`(토크 OFF) / `잠금 정지`를 카드에 노출한다.
- 2026-10-17 기록값: 잠김 3064, 열림 2837.

### 2.6 Jetson 기동 절차 (레포 = 이 PR 체크아웃, 세션 디렉터리 = `~/pr12-arm-session`)

1. 세션에 `config/local_arm_bench_teleop.yaml`을 `session.yaml`로, 자세·볼락 파일을
   `arm_poses.json`·`lock_points.json`으로 복사하고 `ops_console.token`(0600)을 만든다.
2. `extreme-robot-ros2` 컨테이너를 `--network host --privileged -e ROS_DOMAIN_ID=78`,
   `-v 세션:/session -v /dev:/dev -v 레포:/ws:ro`로 띄운다.
   `/ws`에서 `bash scripts/build_arm_console_runtime.sh /session/runtime`을 실행하고
   `source /session/runtime/install/setup.bash`를 마지막에 적용한다.
   이 스크립트는 `extreme-robot`의 브리지와 공유 메시지·브로커만 빌드해 동명 패키지 혼입을 막는다.
3. **`/sys/bus/usb-serial/devices/ttyUSB0/latency_timer`를 1로** 쓴다(재연결·재부팅 시 16으로 복귀).
4. 브리지(`--params-file /session/session.yaml`, `PYTHONUNBUFFERED=1`) → ops 브로커
   (`port:=29001`, `ARM_LOCAL_ALL_AXES=1`; 19001은 운영 스택이 사용) → `arm_console_bridge`.
5. 콘솔은 Jetson 호스트에서 `ssh -Y -C -o ServerAliveInterval=5` 로 띄운다.
   `ARM_LOCAL_ALL_AXES=1 ARM_LOCAL_WRIST_IGNORE_LOCK=1`, `--ops-port 29001`.
   Jetson 호스트에 gst-libav가 없으면 이미지의 `libgstlibav.so`와 누락 라이브러리를
   세션 하위 폴더에 두고 `GST_PLUGIN_PATH`/`LD_LIBRARY_PATH`로만 적용한다.
   **패드를 노트북에 꽂는 경우**에는 콘솔을 노트북에서 `scripts/open_jetson_arm_console.sh`로 띄운다.
   토큰을 가져오고 SSH 터널(`-L 29001:127.0.0.1:29001`)을 연 뒤 콘솔을 실행한다.
   이때 Jetson의 `arm_console_bridge`는 `console_host:=<노트북 IP>`로 띄워야 UDP 상태가 노트북에 도착한다.
   시스템 python에 `pygame`이 없으면 `ARM_PAD_PYTHONPATH=<pygame 경로>`를 준다.
6. GUI에서 `수동 제어 요청` → 조작. 브리지를 재시작하면 모드는 FSM으로 돌아간다.
   GUI만 재시작해도 제어권을 다시 요청해야 한다.

기존 세션의 영점·저장 자세·볼락 기록을 새 예제 파일로 덮어쓰지 않는다.
현재 예제의 `auto_tool_detection: true`만 기존 `session.yaml`에도 반영했는지 확인한다.
팔 관절 키보드 조그와 도구 패드 조그는 모두 인증 연결의 시각 오프셋으로 브로커가 기한을
Jetson 단조시계로 바꿔 전달하므로 별도 노트북의 GUI에서도 쓸 수 있다(2026-10-23 실물 확인).
⚠️ 이전 브로커는 팔 조그 기한을 그대로 비교해 노트북 GUI의 조그를 전부 거부했고,
STOP만 브리지에 도착했다. 조그가 안 움직이면 브로커가 이 수정본인지 먼저 확인한다.

**도구 없이 팔 조작(2026-10-23 사용자 지시)**: 도구 분리·준비 안 됨·하드웨어 오류 사유는
도구 버튼만 막고 팔 1~5축 조그·저장 자세는 막지 않는다. 키보드 조그는 연결된 팔 축이 하나라도
있으면 열린다(5축 필수 아님). 수동 제어권·LIVE·비상정지·브리지 관절 제한/전류 트립은 유지된다.
연결되지 않은 축의 자세 값은 건너뛴다.

### 2.7 도구 자동 인식과 패드

- 브로커와 `extreme-robot` 브리지를 같은 빌드로 갱신한다. 신규 `/tool/manual_command` 수신기가
  없는 `ros2/src/dynamixel_control`의 구 설치본을 함께 source하면 안 된다.
- 자동 감지는 기본 0.5초 주기·같은 결과 2회 확인이다. 단일 ID5, 듀얼 ID3/4, 클리너 ID2를 구분한다.
  장착된 도구의 모터만 버스에 응답하는 배선이 전제다. 여러 도구가 동시에 연결된 구성에서
  실제 장착 도구를 고르는 센서 기능은 없으며, 기계적 체결도 이 인식으로 확인할 수 없다.
  FULL_ROBOT 수동 벤치에서는 팔 FSM이 없어도 실제 팔 정지·예약 이동 없음으로 교체를 허용한다.
  FSM이 작업 중이라고 보고하거나 팔이 움직이면 전환을 기다리며 팔을 임의로 멈추지 않는다.
- 교체 시 도구 세대를 갱신하고 이전 도구의 입력을 거부한다. 도구 종류·상태·동기 상태는 실제 수신값으로 표시한다.
  자동 인식은 기계적 체결 확인이 아니며, 교체 뒤에는 `도구 토크 활성화`를 명시적으로 누른다.
- `패드로 팔·도구 조작`을 켜고 버튼을 모두 놓은 뒤 조작한다(토글이 꺼져 있으면 패드 프로세스가 뜨지 않는다).
  Xbox X/B는 열기/닫기, 클리너에서는 좌/우 회전이다. A는 현재 도구만 소프트 정지(토크 유지),
  Y는 도구 토크 해제다. DualSense는 각각 □/○/×/△다.
- **패드 팔 조작(2026-10-23)** = 키보드 텔레옵을 패드로 한다. LB/RB(L1/R1) 축 선택 1↔5,
  십자키 ↑/↓ 누르는 동안 선택 축 +/− 조그, ←/→ 속도 단계 −/+. 도구 없이도 동작한다.
  선택 축은 키보드 텔레옵 패널과 하나의 값을 공유해 패드로 바꾸면 패널 축 버튼이 따라 바뀐다.
  조그 중 축을 바꾸면 이전 축을 멈추고 십자키를 놓았다 다시 눌러야 새 축이 움직인다.
  키보드와 같은 조그 경로라 제어권·기한·관절 제한·전류 트립이 같고, 자유 지정(토크 OFF) 중에는
  브리지가 `wrist hardware error or torque OFF`로 거부한다 — `자유 지정 해제` 후 조작한다.
  Xbox Series X USB 실측: A0 B1 X2 Y3 LB4 RB5, 십자키 = hat 0(왼쪽 스틱 축 0/1과 구분).
- 통합 운용 모드에서는 차체 주행 해제 뒤 팔 패드를 켤 수 있고, 켜져 있는 동안 차체 입력은 중립이다.
  차체로 돌아갈 때도 버튼·스틱을 모두 놓아야 새 주행 입력이 전달된다.
- 창 포커스·수동 탭·패드 연결·도구 세대를 잃으면 누름 입력을 끝내고, 복귀 후 새 누름부터 받는다.
  도구 조그는 최대 0.6초 수신 기한을 갖는다. 클라이언트 대기·전송·ROS 큐 지연으로 기한이 지난 요청은 거부한다.
  연결 단절이나 GUI 정지 시에는 수신측이 홀드하며 정상 해제 때 토크를 끄지 않는다.
- 듀얼 좌·우 버튼은 각각 ID3/4만 지령한다. 동기 조작은 양쪽 검증된 끝점 비율로 이동한다.
  키보드 조그 속도는 0~10단(기본 5단)이며 기존 스텝의 0~2배, 서보 속도·가속도 상한은 유지한다.
- 패드 Python에는 `pygame`이 필요하다. 단독 GUI는 기본 GUI 인터프리터를 쓰며 필요하면
  `ARM_CONTROLLER_PYTHON=/절대/경로/python3`로 지정한다. 인식하지 못하는 패드 이름에는 임의 매핑을 적용하지 않는다.
- `ROS_DOMAIN_ID=77 ROS_LOCALHOST_ONLY=1 xvfb-run -a python3 scripts/verify_arm_console_tools_mock.py`
  는 실제 설치 ROS·GTK·TCP·UDP와 가상 패드/모터의 운용 검증이다. 실물 장치는 열지 않는다.

### 2.8 슬롯 기반 엔드이펙터 교체 (2026-10-23, 도구 없는 동작 시험 실물 확인)

키보드 텔레옵 탭의 `도구 교체 (슬롯)` 카드. 수동 제어권·FULL_ROBOT·비상정지 없음에서만 동작한다.

- **슬롯 티칭(자세 2개)**: 슬롯마다 4축 머리를 바닥으로 향한 **① 체결 자세**와 머리 방향을 유지한
  **② 그 5cm 위 자세**를 저장한다. 5축 전부 연결·정지 상태여야 한다. ②는 같은 슬롯·같은 도구의 ①이
  있어야 하고, 두 자세의 머리 각도(URDF 부호로 `-q2+q3+q4`) 차이가 5°를 넘으면 거부한다. ①을 다시
  저장하면 이전 ②는 지운다. 도구마다 슬롯 하나(고정). 파일은 `local_tool_slots_file`
  (`/session/tool_slots.json`). ②가 없는 슬롯은 슬롯표에 `(5cm 위 미저장)`으로 표시되고 교체에 쓸 수 없다.
- **교체 흐름**: `이 도구로 교체 시작`. 도구가 달려 있으면 자기 슬롯 ② → ①로 하강 → 분리 → ②로 상승
  → 분리 확인(도구 미감지) 뒤, 요청 도구 슬롯 ② → 하강 → 체결 → 상승 → 장착 확인 → 저장 자세 `home`.
  도구가 없으면 반납 단계를 건너뛴다. `home` 자세(자세 관리에서 이름 `home`으로 저장)가 있어야 시작한다.
- **하강·상승**: ①과 ② 사이를 `rise/step`(기본 10구간)으로 나눠 관절을 선형 보간하고, 브리지가
  `step/speed`(기본 0.5초)마다 경유점을 쓰며 축별 Profile Velocity를 맞춰 모든 축이 함께 도착하게 한다.
  머리 각도가 관절각의 선형합이므로 두 끝이 바닥을 향하면 중간도 바닥을 향한다. 2026-10-23 실측
  5cm 쌍에서 직선 이탈은 계산상 약 2.5mm다.
- **도구 없이 동작만 시험**: 체크하면 체결·분리·도구 확인 단계를 생략하고 이동만 한다(결합 잠금 불필요).
- **관절 제한·전류 트립 토글**: 키보드 텔레옵의 같은 토글이 저장·교체에도 적용된다. 제한 OFF로 저장한
  슬롯은 `limits_checked: false`로 남고, 제한 ON으로 교체를 시작하면 거부된다. 트립 ON이면 교체 중
  1~5축 Present Current가 `local_jog_trip_threshold`(500)를 넘을 때 중단한다.
- **정지·중단**: `교체 정지`는 게이트 없이 항상 전송된다. 정지·수동 제어권 상실·비상정지·단계 시간
  초과·전류 트립·잠금 오류·분리 후 도구 감지·장착 확인 실패는 모두 팔 현재 위치 유지 + 결합 잠금 정지로
  끝난다. 교체 중에는 조그·자세 명령을 브리지가 거부한다.
- ⚠️ **URDF 기구학으로 경로를 계산하지 않는다.** 처음 구현(체결 자세 1개 + IK 수직 경로)은 이 팔에서
  틀렸다: 2·3·4축을 모두 + 부호로 바꾼 추정이 실기에서 머리를 약 90° 돌렸고, URDF 부호로 되돌려도
  실측 5cm 쌍을 맞추려면 2·3축 영점이 약 −23°/−35° 어긋나야 했다. 부호는 URDF 값이 맞고(실측 쌍 차이
  2.6°), 위치는 티칭으로만 정한다. 결합 판정은 자동 감지(ID 응답)라 기계적 체결 증명이 아니다.

## 4. 알려진 제약

- 노트북으로 X11 포워딩한 화면은 무겁다. Jetson 모니터에서 직접 띄우는 것이 가장 빠르다.
- 이벤트 기록(`EventLog._render`)은 항목마다 최근 100줄을 다시 만든다. 고빈도 이벤트를
  기록에 넣으면 GUI가 멈춘다 — 성공한 조그·조그 정지와 그 ACK는 기록하지 않는다.
- 브리지는 레지스터를 개별로 읽는다. FTDI latency 16ms에서는 버스가 포화돼 조그가 만료된다.
- 결합 센서·슬롯 점유 센서가 없다. LOCKED/UNLOCKED는 위치 판정이다.
