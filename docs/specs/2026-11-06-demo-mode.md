# 시연 모드 — 사소한 오류로 주행이 풀리지 않게 하기 (2026-11-06)

사용자 요청: 시연 중에 당장 지장 없는 오류는 무시하고 주행 모드를 유지한다. 사용자가 고른 범위는
네 묶음이다 — (D1) 구동축 오류 자동 복구, (D2) 통신 끊김 뒤 자동 재개, (D3) 로봇팔 없이 주행 허용,
(D4) 영상 없이 운전 시작 허용. 모든 완화는 **시연 모드 스위치를 켰을 때만** 적용하고 기본값은 지금
동작 그대로다. 작업 브랜치 `feat/demo-mode`(main `fb9b922`).

## 0. 바꾸지 않는 것 (시연 모드에서도 그대로 정지)

패드 O·콘솔 긴급 정지와 그 래치 해제 절차, US-100 근접 정지(콘솔 토글로 끄는 기존 방식만 유지),
조향 모터 fault·stale·과전류, DC 버스 저/과전압 등 마스크 밖 구동축 오류, 구동 피드백 stale,
CAN 송신 정지(can_reset), 제어 루프 예외, 세션의 운전 시작 안전 확인(`start_blocker`: 바퀴 정지·
중립 입력·E-stop 미래치·신선도). E-stop은 어떤 경우에도 자동으로 해제하지 않는다.

## 1. 스위치 (로봇·콘솔은 독립 정책)

- 로봇: 호스트 환경변수 `POWERTRAIN_DEMO_MODE`(기본 `false`) → 통합 compose `powertrain_chassis` 환경으로
  전달 → `wp5_control.launch.py demo_mode:=` → `chassis_node` 읽기 전용 파라미터 `demo_mode`.
  참이면 `chassis_node`는 `arm_gate_mode`를 `arm_absent_field`로 쓴다(D3).
  `scripts/robot-start`는 참이면 별도 서비스 `powertrain_demo_autoclear`(프로필 `demo`)를 올리고, 거짓이면
  그 서비스를 `stop`한다(시연을 끄면 시연이 켠 자동 해제도 반드시 꺼진다). 두 자동 해제 서비스는 동시에 돌지 않는다:
  시연 모드면 `robot-start`가 기존 `powertrain_odrive_autoclear`를 `stop`하고, 두 서비스를 함께 요청하면 거부한다.
  ops 상태에 `demo_mode`를 실어 콘솔이 로봇 쪽 상태를 보이게 한다.
- 콘솔: 설정 JSON `demo_mode: true` 또는 `--demo-mode`. 켜지면 헤더에 항상 보이는 배너
  "시연 모드 · 끊김 뒤 자동 재개 · 로봇을 눈으로 보며 운전"을 띄우고, 로봇 쪽 `demo_mode`도 함께 표시한다.
- 로봇 쪽 스위치는 D1·D3, 콘솔 쪽 스위치는 D4를 바꾼다. **D2 자동 재개는 둘 다 켜졌을 때만** 동작한다(콘솔은
  ops 상태의 로봇 `demo_mode`가 참일 때만 자동 시작을 보낸다).

## 2. D1 구동축 오류: 래치 대신 정상 정지 + 단일 소유 오류 해제 (로봇)

검토 결과(자체 검토 절) 주행 중 해당 축만 다시 무장하는 원안은 버렸다 — 일반 `arm()`이 다른 오류까지 지울 수
있고, 0x40만으로는 원인을 구분할 수 없으며, 캐시된 옛 명령으로 재출발할 수 있다.

현재: ARMED 중 구동축 하나가 `axis_state≠8`이거나 `axis_error≠0`이면 CAN 사전 점검(`other_fault`)이
`can_preflight_fault`로 차체를 E-stop 래치하고, 래치 해제는 운용자 `estop_reset`(2단계)이 필요하다.

시연 모드(`ChassisConfig.demo_fault_stop=True`, 로봇 스위치):
- 대상: CAN 사전 점검에서 `other_fault`인 축이 **전부** "신선한 표본 · `axis_state==1(IDLE)` ·
  `axis_error & ~0x840 == 0`(0 포함: 자동 해제가 먼저 지운 경우)"이고, 조향이 신선·정상이며, 다른 E-stop
  원천·hold·CAN 복구 진행이 없을 때. 하나라도 벗어나면 지금처럼 E-stop.
- 동작: E-stop 래치 대신 기존 `disarm()`으로 전 축 정지(구동·조향 IDLE, 목표 0)한다. 래치가 아니므로
  운용자 `estop_reset`이 필요 없다. 정지 이유 `demo_fault_stop:<wheel>:node<n>:0x<err>`를 기록·발행한다.
  **차체는 축을 다시 무장하지 않는다** — 재시작은 정상 운전 시작 경로(바퀴 정지 증명·중립 입력·1.5 s)로만
  한다(D2 또는 사람).
- 한도: 60 s 안에 3번째 시연 정지부터는 지금처럼 E-stop 래치(`demo_fault_stop_budget`). 원인이 계속되면
  사람 판단으로 넘긴다.
- 판정 표본: CAN 6축 구성이면 입력 신선도와 관계없이 사전 점검 표본으로 판정한다(구현 중 바뀜 — 아래 "구현 중
  바뀐 것"). 완화는 **모든** 구동축 피드백이 신선할 때만 한다. USB·fake 구성은 바꾸지 않는다.

오류 해제(단일 소유, 로봇 스위치로 켜지는 `powertrain_demo_autoclear`):
- `odrive_auto_clear.py`에 `--motor-allow` 모드를 더한다. IDLE 축 heartbeat의 축 오류가 마스크(시연 서비스는
  `0x40|0x800`) 안이면 **먼저 `GET_MOTOR_ERROR`만** 보내고, 응답의 `motor.error`가 허용 목록(`0x1000`
  CURRENT_LIMIT_VIOLATION, 0 포함) 안이고 최신 heartbeat가 여전히 IDLE·마스크 안일 때만 `Clear_Errors`를
  보낸다. 응답이 0.3 s 안에 없거나 허용 밖이면 지우지 않고 로그만 남긴다(사람 판단). 재무장은 하지 않는다.
- 남는 위험(수용): 펌웨어 `clear_errors`에는 기대 오류값을 비교하는 조건이 없어, 마지막 확인과 clear 처리 사이(수 ms)에
  새 오류·CAN 복구 래치가 생기면 함께 지워질 수 있다. 펌웨어 조건부 clear는 이번 범위 밖이다. 완화: 시연 서비스는 축마다
  60 s에 3회까지만 지우고, 매번 축·축 오류·motor.error를 경고 로그로 남긴다. 시연 모드에서만 적용된다.
- 조회와 clear의 짝: 조회는 IDLE·마스크 오류 heartbeat 하나에 묶고 0.3 s 안에 응답이 와야 한다. 응답 뒤 **다음
  heartbeat가 같은 축 오류·IDLE**이면 그때 clear한다. 그 사이 상태·오류가 바뀌거나 시간이 지나면 묶음을 버린다.
- 차체(D1)는 오류를 지우지 않는다. 로봇 시연 모드의 운전 시작(`ChassisManager.arm`)은 **오류를 지우지 않는
  무장**을 쓴다: 각 구동축을 무장하기 직전에 수신을 비우고 축 오류가 정확히 0인지(0x4000 포함 어떤 비트도 없음)
  다시 확인하며, 하나라도 있으면 무장을 거부한다(E-stop 아님, 시작 실패 — 차체는 `disarm_cause=arm_refused`로 정지). 통과하면 CLEAR_ERRORS 없이 속도 제어
  →0→CLOSED_LOOP만 보낸다. 그 뒤 오류가 생기면 펌웨어가 폐루프를 거부하고 기존 무장 확인 시간 초과로 E-stop된다.
  (시연 모드가 아니면 지금처럼 CLEAR_ERRORS를 보낸다.)
- `--motor-allow`를 주지 않은 기존 `odrive-autoclear`는 지금과 동일하다.

## 3. D2 통신 끊김 뒤 자동 재개 (콘솔, `OperationRuntime`)

현재: 세션 임대 만료·입력 채널 끊김·패드 분리·D1 시연 정지가 주행을 해제(DISARM)하면 사람이 운전 시작
(1.5 s 누르기)을 다시 해야 한다. 로봇 세션은 `start_begin` 뒤 1.5 s가 지나야 `start`를 받고, 시작마다
`start_blocker`(바퀴 정지 증명·게이트웨이 신선 중립 입력·E-stop 미래치·신선도)를 다시 확인한다.

시연 모드(콘솔 스위치):
- 자동 시작은 서버에 표시한다: 세션 `start` 요청에 `auto: true`를 싣고, 서버 `ManualDriveService`는 자동 시작이면
  (1) 로봇 `demo_mode`가 아니면 거부, (2) 권한·게이트웨이에 MOTION_HOLD가 있으면 `clear_transient_hold` 없이 거부,
  (3) 무장은 D1의 오류를 지우지 않는 무장(차체 시연 모드)으로만 한다. 사람 시작은 지금과 같다.
- 비교-후-무장: 자동 `start`에는 콘솔이 판정에 쓴 `expect_stop_seq`·`expect_disarm_seq`를 싣는다. 세션은 잠금 안에서
  `stop_seq`를 비교하고, 무장은 일반 `arm` 대신 ops 액션 `demo_auto_arm`(params `expect_disarm_seq`)으로 보낸다.
  `chassis_node`는 이 요청을 다른 disarm·arm 서비스와 같은 실행기에서 처리하며, 차체 `disarm_seq`가 기대값과 같을 때만
  오류를 지우지 않는 무장을 한다(다르면 거부). 따라서 자동 시작이 접수된 뒤 사람이 다른 경로로 해제하면 무장되지 않는다.
- 정지 원인은 로봇이 알린다. 세션 스냅숏에 `stop_cause`(`revoke` = 임대 만료·채널 끊김, `operator` = 콘솔 주행 해제,
  `service` = 서비스 종료)와 `stop_seq`를, ops 상태에 차체의 `disarm_cause`(`demo_fault` = D1 시연 정지,
  `command` = ops disarm 명령)와 `disarm_seq`를 싣는다. 콘솔은 의도를 켤 때 두 seq를 기억하고, 그 뒤 바뀐 원인이
  다음 두 경우에만 자동 재개한다 — (a) 연결된 채로 `disarm_seq`가 정확히 1 늘고 원인이 `demo_fault`(D1 정지를 실시간
  관측), (b) 끊김 뒤 재연결에서 `stop_seq`가 정확히 1 늘고 원인이 `revoke`이며 `disarm_seq`가 정확히 1 늘었다(그 revoke의
  disarm). seq가 그보다 더 늘었거나(관측 못 한 다른 정지), 연결된 채로 `command`·`operator` 원인을 보면 의도를 끈다.
- 운전 의도(`drive_intent`)는 운전 시작 성공 뒤 ARMED를 본 순간 켠다. 다음 중 하나면 끄고, 그 뒤 재개는 사람이
  운전 시작을 눌러야 한다: 운용자 `주행 해제`, 콘솔 긴급 정지 요청, 로봇 상태의 E-stop 래치·활성 E-stop 원천,
  **패드 E-stop 누름(자식 프로세스가 E-stop 이벤트를 만든 순간 부모 상태로 알린다)**, 패드 자식 프로세스 재시작,
  로봇 `boot_id` 변경, 의도를 잃은 뒤(연결 끊김·DISARM 관측) 120 s 경과.
- 자동 재개 조건: 의도가 켜져 있고, 로봇 연결됨, 차체가 ARMED가 아님(DISARM·IDLE), E-stop 래치·원천 없음,
  권한·게이트웨이 어디에도 MOTION_HOLD 없음(있으면 원인을 모르므로 의도를 끄고 사람 시작 — 시작 경로의
  `clear_transient_hold`를 자동으로 타지 않는다), 정지 원인이 위 허용 원인,
  기존 준비 조건 전부 참이며 **전방 영상 LIVE도 참**(D4 완화는 사람이 누르는 시작에만 적용). 그러면 콘솔이
  1.5 s 누르기를 대신 시작한다 — 기존 `start_begin` → 1.5 s → `start` 경로 그대로이고 준비가 깨지면 취소한다.
  실패하면 3 s 뒤 다시 시도한다.
- ARMED인데 권한·게이트웨이가 MOTION_HOLD인 경우도 자동으로 풀지 않는다(사람이 주행 해제 → 운전 시작).
- 로봇 쪽 안전 확인은 그대로라 자동 재개도 중립 입력·바퀴 정지 없이는 성사되지 않는다. 자동 재무장 뒤 새
  데드맨·트리거 입력은 곧바로 주행이 되므로, 재개 순간 배너와 패드 진동(가능하면)으로 알린다.

## 4. D3 로봇팔 없이 주행 허용 (로봇)

로봇 시연 모드면 `arm_gate_mode=arm_absent_field`. `/arm_status` 발행자가 0일 때만 내부 STOWED_LOCKED로
신선도를 대신하고, 이전에 본 GRIP_LOST·계약 위반 래치는 그대로 주행을 막으며, 팔 프로세스가 돌면 정상 게이트가
작동한다(기존 동작). 컴포넌트 토글은 건드리지 않는다.

## 5. D4 영상 없이 운전 시작 허용 (콘솔)

콘솔 시연 모드면 **사람이 누르는** 운전 시작의 준비 조건에서 "전방 영상 수신 대기" 하나만 뺀다. 자동 재개(D2)는
영상 LIVE를 계속 요구한다. 배너가 눈으로 보며 운전하라는 뜻을 같이 쓴다.

## 6. 시험·검증 계획

- D1: `ChassisManager` + 가짜 CAN 구동(기존 CAN 복구 시험과 같은 capability 경로)으로 (a) 0x40·0x800·0(IDLE) →
  E-stop 없이 DISARM·이유 기록, (b) 마스크 밖·비IDLE·stale·조향 stale·다른 hold → 기존 E-stop, (c) 60 s 3번째 →
  E-stop, (d) 시연 꺼짐 → 기존과 동일(회귀), (e) DISARM 뒤 차체가 스스로 재무장하지 않음.
- autoclear: `--motor-allow`에서 조회만 먼저, 허용 응답 뒤에만 clear, 허용 밖·무응답·상태 변화면 clear 없음,
  `--motor-allow` 없으면 기존 동작(회귀).
- D2: `OperationRuntime`에 가짜 세션·자식 상태로 (a) 끊김 뒤 재연결 → 자동 start_begin/start, (b) 주행 해제·E-stop
  래치·패드 E-stop 이벤트·자식 재시작·boot_id 변경·120 s 경과 → 자동 재개 없음, (c) ARMED+HOLD → 자동 없음,
  (d) 영상 없으면 자동 재개 없음(사람 시작은 D4로 가능), (e) 시연 꺼짐 회귀.
- 스위치: launch/compose/robot-start(켜면 서비스 up, 끄면 stop) 시험, chassis_node 파라미터→arm_gate_mode,
  ops 상태 `demo_mode`, 콘솔 배너·준비 조건 시험.
- 실행 검증: Humble 컨테이너에서 설치 엔트리포인트 `chassis`(fake)·`ops_broker` 시연 모드 기동 스모크, 콘솔
  `runtime_smoke`(시연 켜고·끄고), 젯슨 배포 뒤 컨테이너 무크래시. 실차 오류 주입은 하지 않는다.

## 자체 검토

- ② Codex 적대 검토(1차)·③ 독립 검토(결론 비공유) 공통 P1: 주행 중 단일 축 재무장 원안은 일반 `arm()`이
  점검 뒤 생긴 다른 오류·CAN 복구 래치까지 지움, 0x40만으로 원인 구분 불가(motor.error 미확인), 사전 점검 HOLD가
  첫 tick 지령을 막지 못함, 캐시된 옛 명령이 300 ms 안이면 재출발, 복구 축 keepalive·encoder 조회 부재,
  패드 미확인 E-stop을 콘솔이 모름, 컴포넌트 끄기는 GRIP_LOST까지 무시. P2: autoclear와 경쟁, 0x800 정지 증명
  무효, HOLD 원인 구분 불가, 의도 만료·boot_id, 스위치 OFF 뒤 서비스 잔존, 영상 없는 자동 재개.
  → D1을 "래치 대신 정상 정지 + 단일 소유 해제(motor.error 허용 목록) + 정상 시작 경로로만 재무장"으로,
  D2에 패드 E-stop 이벤트·자식 재시작·boot_id·120 s 만료·ARMED+HOLD 제외·영상 LIVE 요구를,
  D3을 `arm_absent_field`로, 스위치를 독립 정책 + 시연 전용 서비스 up/stop으로 바꿨다.
- ② 재검토(2차): 정상 시작 `arm()`도 정지 증명 뒤 생긴 오류를 지움(P1), D2가 DISARM·HOLD 원인을 구분 못 해 계약 위반
  HOLD를 revoke 뒤 자동으로 풂(P1), 기존 autoclear가 허용 목록을 우회(P1), 조회 응답과 heartbeat 사건 불일치(P2).
  → 로봇 시연 모드 시작은 직전 재확인 + CLEAR_ERRORS 없는 무장, 세션 `stop_cause`·차체 `disarm_cause`와 seq로 허용
  원인만 재개·어떤 HOLD든 자동 안 함, 두 autoclear 동시 실행 금지, 조회–clear를 다음 heartbeat 확인으로 묶음.
- ② 재검토(3차): 콘솔만 켠 경우 자동 시작이 오류 해제형 arm을 부름·검사 뒤 생긴 HOLD를 서버가 자동 해제(P1), 마지막
  cause/seq로는 중간의 사람 해제를 못 가림(P1), 조회–clear 잔여 경합(P2). → 자동 시작 `auto` 표시와 서버 강제(로봇 demo 필수·

- ② 재검토(4차): 자동 시작 접수 뒤 최종 arm 전 사람 disarm을 서버가 모름(P1). → 기대 seq를 싣고 세션(stop_seq)·차체
  (`demo_auto_arm`, disarm_seq) 비교-후-무장. 그 밖의 새 P1/P2 없음(잔여 clear 경합은 수용 위험으로 재지적 안 됨).
