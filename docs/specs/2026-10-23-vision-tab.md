송신 경로·단위/부호 계약이 완성됐다는 의미는 아니다. 자세·보정 연결은 4단계에서 검증한다.

## 화면 구성과 소유권

3단계 구현: 단일 지도 작업 스레드가 Top·Oblique를 한 쌍으로 약 2 Hz 생성한다.
캐시는 작업 스레드 소유이며, GTK는 완성된 premultiplied BGRA 래스터만 그린다.
설정/결과는 최신 한 개만 보관하고 숨김 시 계산·UI 타이머를 중지한다.
숨기기·크기/시점 변경 전 결과는 세대 번호가 맞을 때만 게시한다.
Top은 기존 클래스·범례를 유지하고, Oblique만 JSON 정책으로 재분류한다.
잡음 필터가 제거한 위험 셀은 통과로 낮추지 않고 미확인 처리한다.
송신 코드와 표시 기준의 문턱이 다를 수 있으므로 송신 FREE로 표시 위험을 취소하지 않는다.

Top 따라가기는 로버 전방을 포함하도록 시야를 배치하며 방향이 위가 된다.
따라가기 해제 후 Top은 북쪽이 위, Oblique는 선택한 위치·마지막 시점 방향을 기준으로 한다.
Oblique 격자 원점은 로버 base이며 확인되지 않은 카메라 장착 평행이동을 추정하지 않는다.
전방 범위는 기본 2.5 m, 줌 연동·최대 160×160 셀로 제한하며 실제 범위를 화면에 표시한다.
확인된 현재 자세가 없거나 상태 패킷이 0.5 s를 넘으면 Oblique를 투영하지 않는다.
Top의 과거 기록·마지막 위치는 끊김 표시와 회색 화살표로 구분한다.

기준값 CLI는 두 진입점 모두 `--l515-criteria`, `--l515-criteria-profile`, JSON 키는
`l515_criteria`, `l515_criteria_profile`이다. 파일 교체/설정 변경 후 콘솔 재시작으로 적용한다.
v0.2 기본 A_no_stop와 B_stop20 프로필을 지원한다.
패키지 재사용을 위해 lidar_dev/live_map.py·obstacles_map.py의 import만 스크립트/패키지
양쪽을 지원하게 바꿨으며 알고리즘은 변경하지 않았다. 광민의 네 지도 영역은 수정하지 않는다.

한 페이지에 2×2 영역을 두고 위쪽 L515 카메라 / 차체 상태,
아래쪽 Top / Oblique 지도를 동시에 표시하는 안을 사용한다.
좁은 화면에서도 네 영역을 유지하며 실제 최소 크기는 구현 단계에서 확인한다.

1. 기존 `self._l515` VideoPanel 전체를 오버레이와 함께 비전 슬롯으로 옮긴다.
   gtksink 위젯은 한 부모만 가질 수 있다. 새 VideoPanel이나 tee/sink를 만들지 않는다.
   진입 시 L515가 메인인지 PiP인지와 원래 부모를 기록하고, 이탈 때 복원한다.
   D435가 메인인 경우도 처리하고, 비전 진입 중 V/화면 전환 동작과
   부모 위젯 크기 할당 콜백이 서로 충돌하지 않도록 한다.
2. 오버레이 체크 상태는 기존 `overlay_view_state["show_terrain"]`와 공유한다.
   두 탭의 버튼을 동기화하고 재진입 때 기존 설정을 유지한다.
3. `self._map_receiver`의 스냅숏을 두 지도 작업에 제공한다.
   Top은 기존 MapRenderer를 호출하며 캐시는 작업 스레드별로 별도 소유한다.
   기존 MapPanel은 그대로 보존한다. 해당 위젯의 draw를 새 화면에 호출하지 않는다.
4. Oblique는 `lidar_dev/live_map.py`의 로컬 격자·필터·분류·색상·투영을 재사용한다.
   `cv2`를 사용하며 스크립트/패키지 import 호환 처리를 적용했다.
   자세 미수신 때 함수의 `(0,0,0)` 기본 자세로 가상 지도를 만들지 않도록 호출 전 막는다.
5. 자세 패널은 `self._chassis_receiver`의 실제 값을 사용한다.
   RoverCoordinationGraphic을 수정 없이 재사용할 수 있다. 현재 그림의 투영은
   사용자가 바꾸는 시점 yaw를 사용하며 roll/pitch로 차체를 기울이지 않는다.
   이 그림은 차체·바퀴 상태의 개략도임을 밝히고, 원시 IMU 수치는 별도로 표시한다.
   보정이 확인되기 전 원시값을 차체 그림의 기울기에 적용하지 않는다.

## 데이터와 유효성

| 항목 | 기존 경로 | 표시 원칙 |
|---|---|---|
| L515 영상 | SRT :5000, self._l515 | 기존 FPS·마지막 프레임 나이·연결 상태 재사용 |
| 카메라 지형 | UDP :5009, self._terrain_receiver / TerrainCanvas | 링크 0.5 s, 깊이 0.6 s 기준 및 해상도 정합 검사 보존 |
| 두 지도 | UDP :5010, self._map_receiver | 상태 패킷 나이 0.5 s 초과 시 STALE, 타일만 수신해도 자세 LIVE로 판정하지 않음 |
| IMU roll/pitch | UDP :5005, TelemetrySnapshot | 'IMU 원시값(L515 기준·보정 미확인)'으로 표시 |
| 바퀴 | wheel_statuses[].steer_deg / drive_turns_per_s / stale | 바퀴별 결측·stale를 각각 검사, 속도 단위 rev/s 명시 |
| 보정된 차체 자세 | 현재 확인된 계약 없음 | '보정 미확인'; 약 19.5° 일괄 차감 금지 |
| 로커·보기 AS5048B | 현재 전송·파서 필드 없음 | 선택 필드와 출처·측정 나이 인터페이스 마련, 없으면 '미수신' |
| 지도 기준면 | status.plane_tilt | age_ms/1000 + 상태 수신 후 경과, 1 s 초과 시 최신값처럼 표시하지 않음 |
| 지도 중력 자세 | status.gravity | 정지 구간 전용, '정지 측정 · n초 전', 주행 자세와 분리 |

각 값의 연결 상태와 값 자체의 유효성은 분리한다.
처음에는 미수신, 수신 후 기준 초과는 오래됨/수신 끊김,
유효 패킷 재수신 때 복구를 표시한다. 마지막 숫자를 남기면 반드시 오래된 값임을 표시한다.
현재 텔레메트리는 패킷 수신 시각만 있고 IMU의 원 측정 시각은 없다.
따라서 이를 '측정 후 경과'로 부르지 않고 '패킷 수신 후 경과'로 표시한다.
송신기는 1 s 넘은 자세를 null로 보내므로 새 패킷이라도 자세가 없을 수 있다.
바퀴 Hall 값은 0.3 rev/s 아래에서 실제 정지와 다를 수 있다는 표시 단서를 둔다.

AS5048B 선택 필드는 다음 자세 단계에서 이름·단위·부호·채널 구조를 문서화한다.
송신 코드가 없으므로 파서만 추가해도 실제 연결 완료로 판정하지 않는다.
gravity에는 독립 측정 시각이 없으므로 동봉 plane_tilt.age_ms와 상태 수신 시각으로
나이를 계산하고, 근거가 없으면 나이를 임의 생성하지 않는다.

## 확인된 데이터 한계

`:5009` TerrainFrame은 ground 상태·높이·장착각과 최대 4개 장애물 polygon을 전달한다.
**바닥 영역의 mask/polygon은 전달하지 않는다.** 현재 TerrainCanvas는 장애물 윤곽과
바닥 상태 배지를 그리며, 시험대의 초록색 바닥 전체 칠하기와는 다르다.
기존 데이터만 사용하는 범위에서는 바닥 상태 + 장애물 윤곽을 재사용한다.
바닥 영역을 실제로 칠하는 요구는 미충족으로 추적한다. 이를 완료하려면 추가 데이터
계약에 대한 합의가 필요하며, 콘솔에서 깊이 재계산이나 가짜 바닥 영역으로 대체하지 않는다.

현재 overlay packet은 비디오 프레임과 공유하는 정확한 프레임 식별자가 없다.
`--terrain-display-delay-ms` 0–400 ms(기본 0)를 기록하고 실기에서 좌표·지연을 확인한다.
해상도가 맞는다는 사실만으로 시간 정합 검증을 완료하지 않는다.

장착각은 요청의 약 19.5°, 문서에 언급된 URDF 15°, 옛 지도 기본 20°가 불일치한다.
`imu_tilt_node`의 base_link→l515_link 고정 회전은 단위회전이며,
`/imu/filtered`는 base_link로 표기된다. 메시지 frame 이름만으로 보정됐다고 판단하지 않는다.
광민·도현의 좌표계·부호·영점·장착 회전 적용 방식 확인 전까지 차체 보정은 미확인이다.
외부 메시지 발송은 수행하지 않았으며 사용자가 확인 내용을 전달하면 반영한다.

## 기준값과 지도 조작

- 경로 이름은 `L515_CRITERIA`와 맞추고 CLI 및 통합 설정 JSON을 지원한다.
  우선순위 제안: 명시 CLI > 설정 JSON > 환경 변수 > 저장소 v0.2 기본값.
  프로필 선택·버전·프로필·SHA256을 표시하고 잘못된 파일은 명시적 오류 처리한다.
- `load_criteria`를 재사용하며 v0.2 기본 A_no_stop 및 B 프로필을 지원한다.
  trench_depth_m이 없으면 step_up_m으로 보수 대체한다.
- 기존 Top MapRenderer 색은 송신 지도 클래스(돌출/도랑·낙차/주행 가능/관측 부족/미관측)다.
  v0.2의 통과/주의/불가 재분류와 같지 않다. Top에는 기존 범례와 송신 기준값,
  Oblique 재분류에는 v0.2 프로필 범례를 각각 표시한다. 하나의 기준인 것처럼 보이지 않게 한다.
- 확대 휠 ×1.2, 끌기 시 따라가기 해제, 로버 따라가기, 위치·방향 화살표를 제공한다.
  Oblique는 로컬 격자 기준의 조작 의미를 설명하고, 미수신 자세를 원점 화살표로 표시하지 않는다.
- 지도는 관측 기록이며 실시간 주행 허가·안전 제어 입력이 아니라는 기존 주석을 유지한다.

## 성능과 검증 계약

- 지도 이미지는 작업 스레드에서 각 약 2 Hz로 생성한다. 대기열을 쌓지 않고 최신 요청만 처리한다.
  메인 스레드는 위젯 상태와 준비된 이미지 그리기만 수행한다.
- 탭 비표시 시 비전 전용 계산·갱신을 중지한다. 수신기와 기존 비디오 디코딩은 유지한다.
  이탈 직후 이미 진행 중인 결과가 복귀 후 화면을 덮지 않도록 세대 검사한다.
- 실제 GTK 정지 시간과 GIL 경합을 측정하고 필요하면 프로세스로 분리한다.
  시험대 6–8→23–25 fps 결과는 지도 런타임 분리 결과이며 콘솔 렌더링의 보장값이 아니다.
- numpy import 전에 OPENBLAS_NUM_THREADS=1: app 직접 실행, 통합 __main__, systemd,
  jetson_gui_up 안내 경로를 함께 다룬다. 한글은 PangoCairo layout을 크기 제한 캐시로 보관한다.
- sync=false 유지, 오래된 영상 프레임을 버리는 경로를 검증한다.
- runtime_smoke에 비전 생성·탭 전환·정상/미수신/오래됨/끊김/복구·누락값·숨김·종료 검사를
  추가하고 의도한 고장에 FAIL하는 음성 대조를 수행한다.
- 실제 Gateway+L515로 600 s 실행: 기존 영상과 같은 FPS, 정지 >0.5 s 없음,
  Top/Oblique 각각 약 2 Hz, CPU/RSS/지연 기록. 이전/이후 같은 부하·전원·클럭 조건 비교.
- 실시간 화면 복귀 시 원래 메인/PiP·화면 전환·오버레이 상태 회귀 검증.
  중복 영상 연결/디코더·지도 포트 없음도 확인한다.
- 실제 로봇 확인이 안 되면 단위/합성 시험과 구분해 미검증으로 남긴다.
