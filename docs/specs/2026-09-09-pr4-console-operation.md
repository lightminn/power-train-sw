## 화면과 동작

- PR의 실시간 화면/시스템 상태 두 탭, 색상, 카메라 PiP, 도구·환경 팝업을 유지한다.
- 통합 진입점 `python -m operator_console`의 자동 재연결·패드 자식 관리·1.5초
  명시적 운전 시작·주행 해제·상시 긴급 정지를 유지한다. 자동 arm은 추가하지 않는다.
- 상단의 작은 `복구 · 설정` 버튼으로 기존 token-gated OpsPanel을 비모달 별도 창에
  표시한다. 경고 초기화·컴포넌트·조향 모드·기존 고급 조작을 유지한다.
- 팝업 닫기/초점 상실 시 진행 중 확인/홀드 동작을 취소한다. 콘솔 종료 시 자식 창과
  네트워크·패드 자원을 정리한다. 팝업을 여는 것으로 명령을 보내지 않는다.
- 기존 main 운용 문서의 `관리자 조작` 접근 경로를 새 버튼/창 경로로 갱신한다.
- 통합 진입점에서 환경 수신 포트도 명시적으로 설정·검증할 수 있게 한다.
- 직접 렌더에서 확인한 통합 운용 패널의 글자 대비와 복구 창의 테마 누락을 해당
  컨테이너에 한정해 보정한다. 일반 노트북 크기에서 조작이 잘리지 않게 확인한다.
- 인증 세션 변경으로 SRT를 다시 연결해도 새 프레임 수신이 복귀해야 한다. 실제
  수신 후 재시작 시 나타나는 demux `not-linked` 결함을 재현하고 최소 수정한다.

## 데이터 표시 계약

- 바퀴 stale, ODrive axis error, 조향 fault, CAN `UNHEALTHY`/unavailable 또는 구동 unavailable이면 새 시스템
  화면의 종합 상태를 준비 완료로 표시하지 않는다. 상세 화면을 숨겨도 이 조건은 유지한다.
- US-100의 안전 판정과 차체의 수동 ESTOP은 다른 원천이다. 차체 `ESTOP/ESTOP` 또는
  wheel FAULT가 있으면 US-100 값이 정상이어도 종합 준비 완료로 표시하지 않는다.
  수동 ESTOP에서는 안전 배지와 비상정지 값도 같은 원천을 반영한다.
- SGP30 예열 중 eCO2/TVOC는 `예열 중`으로 표시하고 정상 센서 개수에서 제외한다.
  CO/LPG의 단순 숫자 표시라는 PR의 의도는 유지한다.
- 실시간 화면의 최근 이벤트는 해당 화면의 활성 필터가 적용된 목록과 일치한다.
- 인식 데이터의 상태 신선도는 기존 상세 화면의 0.25초 기준을 새 시스템 화면과
  공유한다. 화면 overlay의 0.50초 표시 유예는 별도이며 그 계약은 바꾸지 않는다.
- 값이 없거나 stale인 센서를 정상으로 합성하지 않는다. 실제 제어/안전 정책은 기존
  서버와 순수 코어가 소유한다.

## 검증과 인수 경계

회귀 테스트를 먼저 실행하여 실패를 확인한 뒤 구현한다. 실제 GTK 위젯 표시·클릭과
실제 session/ops TCP 경로를 로컬 fixture로 검증한다. 기존 콘솔 전체 테스트,
runtime_smoke, integrated_runtime_smoke를 실행한다. 가능하면 로컬 GStreamer test
source의 실제 SRT 디코드와 가상 패드를 이용해 GUI 시작→수동 권한→arm→해제→ESTOP
및 초기화 경로를 검증한다. 새 검증 게이트는 알려진 결함을 다시 넣어 실패를 확인한다.

최초 provisioning과 로봇 서비스 기동은 필요하다. 콘솔 실행만으로 매일 운용하는 조건을
기존 restart 정책과 비교해 문서화하고 필요한 자동 기동 코드는 로컬에서만 준비한다.
실물 모터·전방 센서·네트워크·부팅/배포 인수는 이번 로컬 검증과 구분한다.

## 부팅 복귀 방식

기존 provisioning은 별도 stack 자동 기동 유닛 대신 Compose restart 정책을 사용한다.
통합 overlay의 전방 카메라(`powertrain_ros`)와 전원 텔레메트리만 `on-failure`여서
Docker 재시작 후 복귀하지 않는 차이가 있다. 이 두 서비스를 나머지 필수 서비스와
같은 `unless-stopped`로 맞춘다. 최초 준비와 `robot-start` 한 번은 필요하며, 이후
운용 중이던 stack은 재부팅 후 복귀한다. 정비를 위해 명시적으로 정지한 서비스는
정지 상태를 유지한다. 콘솔에 SSH 기동이나 자동 arm을 추가하지 않는다.

근거: [Docker restart policy](https://docs.docker.com/engine/containers/start-containers-automatically/).
이번 검증은 병합된 Compose 설정을 확인하며 실제 daemon 재시작/Jetson 부팅은 하지 않는다.
